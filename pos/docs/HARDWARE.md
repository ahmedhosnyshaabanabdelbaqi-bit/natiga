# دليل الباركود والطباعة والأجهزة

> **تصريح صريح:** النظام **لا يدّعي** دعم كل طابعة أو ميزان تلقائيًا.
> ما هو مُختبَر مذكور أدناه، وما يحتاج وسيطًا أو إعدادًا مذكور كذلك.

---

## 1. قارئ الباركود

### الوضع المدعوم: قارئ يعمل ككيبورد (HID)
هذا هو الوضع الافتراضي لمعظم القارئات (USB أو بلوتوث) ولا يحتاج أي برنامج.

**الإعداد المطلوب على القارئ (من دليله):**
1. **Suffix = Enter (CR)** — ليُرسل القارئ سطرًا جديدًا بعد الكود
2. **Prefix = بدون**
3. لوحة المفاتيح: **US English** — لغة عربية تفسد الأرقام
4. عطّل "Caps Lock" الذي يضيفه بعض القارئات

**في النظام:** خانة المسح دائمًا في الأعلى وتستعيد التركيز تلقائيًا بعد كل إضافة،
لكنها **لا تسرقه** أثناء كتابة مبلغ الدفع أو نموذج آخر (`data-keep-focus`).

### الباركود كنص
`barcodes.code` من نوع نصي — `0123` و`123` كودان مختلفان، والأصفار في البداية محفوظة.

### أكثر من باركود للصنف
مسموح، ويمكن ربط باركود مختلف بكل **وحدة بيع** (قطعة / كرتونة) أو بكل **متغير** (لون/مقاس).

### باركود الوزن والسعر (الموازين)
الصيغ تختلف بين موردي الموازين، لذلك **تُعرَّف كإعداد** لا كافتراض.

`settings` → المفتاح `barcode.embedded_formats`:

```json
[
  {
    "prefix": "21",
    "length": 13,
    "item_code": [2, 5],
    "value": [7, 5],
    "value_kind": "weight",
    "value_scale": 3
  },
  {
    "prefix": "22",
    "length": 13,
    "item_code": [2, 5],
    "value": [7, 5],
    "value_kind": "price",
    "value_scale": 2
  }
]
```

| الحقل | المعنى |
|---|---|
| `prefix` | البادئة التي تميّز هذه الصيغة |
| `length` | طول الكود كاملًا |
| `item_code` | `[موضع البداية، الطول]` لكود الصنف |
| `value` | `[موضع البداية، الطول]` للقيمة |
| `value_kind` | `weight` (كمية) أو `price` (مبلغ) |
| `value_scale` | عدد الخانات العشرية داخل القيمة |

مثال: `2100123007500` بالصيغة الأولى ⇒ الصنف `00123`، الوزن `7.500` كجم.

> **الباركود العادي له الأولوية دائمًا:** لا يُعاد تفسير كود موجود فعلًا في النظام.

**مسحة موزونة لا تُدمج** مع مسحة سابقة لنفس الصنف (`mergeable: false`) — كل عبوة سطر مستقل.

## 2. الطباعة

### المستوى الأول (يعمل الآن، بلا أي تثبيت): الطباعة من المتصفح

القوالب الجاهزة:

| القالب | المقاس | الاستخدام |
|---|---|---|
| `receipt-80` | 80 مم | الإيصال الافتراضي |
| `receipt-58` | 58 مم | طابعات صغيرة |
| `invoice-a4` | A4 | فاتورة رسمية / PDF |
| `label-40x25` | ملصق | باركود الأصناف |
| `shift-report` | 80 مم | تقرير إغلاق الوردية |

**إعداد الطابعة الحرارية للمتصفح:**
1. ثبّت تعريف الطابعة من الشركة المصنعة
2. اجعل مقاس الورق `80mm × Roll` (أو 58)
3. في Chrome: الهوامش = **بلا**، «طباعة الخلفيات» = مفعّل، المقياس = 100%
4. فعّل «الطباعة دون مربع حوار» بتشغيل Chrome بـ `--kiosk-printing` إن أردت

**محتوى الإيصال قابل للتخصيص:** الشعار، الفرع، التواصل، رقم الفاتورة، الكاشير،
البنود، الخصومات، الضرائب، طرق الدفع، الباقي، وسياسة الاستبدال.

**العربية:** القوالب `dir="rtl"` والأرقام تُعرض LTR داخل أعمدة بعرض ثابت
(`font-variant-numeric: tabular-nums`) حتى لا تختلط. الأسماء الطويلة تُلف على سطرين.

### إعادة الطباعة
- تُسجَّل باسم المستخدم والوقت (`sale.reprinted` في سجل التدقيق)
- تُوسم بـ **«نسخة»** على الإيصال
- عدّاد `sales.print_count` يزيد

### فشل الطابعة لا يمس البيع
البيع يُعتمد أولًا، ثم تُنشأ **مهمة طباعة** منفصلة:

```
GET  /api/v1/print-jobs/failed      ← قائمة الفاشلة
POST /api/v1/print-jobs/{id}/retry  ← إعادة محاولة مستقلة
```

**لا يُلغى بيع معتمد ولا يُعاد تنفيذه بسبب الطابعة.**

### المستوى الثاني (غير منفَّذ): وسيط محلي للطباعة الصامتة
الطباعة الصامتة، وفتح درج النقدية، وقراءة الميزان، وشاشة العميل تحتاج وسيطًا
محليًا يُثبَّت على جهاز الكاشير. طبقة التكامل مفصولة في `Printing`، لكن الوسيط
نفسه **غير مُنفَّذ في هذا الإصدار**.

عند تنفيذه يجب أن يلتزم بـ:
- الاستماع على `127.0.0.1` فقط
- رمز مصادقة لكل جهاز
- صلاحيات محددة (طباعة وفتح درج فقط)
- توثيق التثبيت والأجهزة المُختبَرة فعليًا

## 3. درج النقدية

| الحالة | السلوك |
|---|---|
| درج موصول بالطابعة الحرارية | يُفتح بأمر ESC/POS ضمن الإيصال — **يحتاج الوسيط المحلي** |
| فتح بدون بيع | مسجَّل دائمًا: `POST /cash/open-drawer` يتطلب صلاحية `cash.drawer.open` وسببًا، ويُقيَّد في التدقيق |

---

## 4. الميزان وشاشة العميل

| الجهاز | الحالة |
|---|---|
| ميزان يطبع باركود موزون | **مدعوم** عبر إعداد الصيغة أعلاه — لا يحتاج اتصالًا مباشرًا |
| ميزان بمنفذ تسلسلي مباشر | **غير منفَّذ** — يحتاج الوسيط المحلي |
| شاشة عميل | **غير منفَّذة** — وحدة اختيارية |

---

## 5. قائمة التوافق واختبار الاتصال

| الجهاز | الحالة في هذا الإصدار |
|---|---|
| قارئ باركود HID (USB/بلوتوث) | ✅ مُختبَر منطقيًا — يعمل ككيبورد، لا يحتاج تعريفًا |
| طابعة حرارية 80/58 مم عبر تعريف النظام | ✅ قوالب جاهزة ومقاسات صحيحة — تحتاج اختبار طباعة على جهازك |
| طابعة A4 / PDF | ✅ قالب جاهز |
| طابعة ملصقات باركود | ✅ قالب بمقاس قابل للتحديد |
| طباعة صامتة / ESC/POS مباشر | ⛔ يحتاج وسيطًا محليًا — غير منفَّذ |
| فتح درج نقدية آليًا | ⛔ يحتاج الوسيط — الفتح اليدوي مسجَّل ومحمي بصلاحية |
| ميزان تسلسلي مباشر | ⛔ غير منفَّذ |
| شاشة عميل | ⛔ غير منفَّذة |

**اختبار عملي قبل التشغيل الحقيقي (افعله بنفسك):**
1. امسح 20 صنفًا متتاليًا وتأكد من عدم ضياع أي مسحة
2. اطبع إيصالًا باسم صنف عربي طويل (أكثر من 40 حرفًا) وتحقق من اللف
3. اطبع فاتورة بكميات كسرية (0.750 كجم) وتحقق من الأرقام
4. افصل الطابعة، أتمّ بيعًا، وتأكد أن الفاتورة اعتُمدت وظهرت في طابور الفاشلة
5. أعد تشغيل الطابعة واضغط «إعادة محاولة» وتأكد من عدم تكرار البيع
