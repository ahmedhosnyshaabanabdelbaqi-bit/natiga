## Rules (BUSINESS_RULES §11)
- Scan flow `POST /admin/deliveries/scan` (delivery officers): token from MembershipQr (purpose pickup) or pickup_authorization token or event registration QR → resolve member → list orders with ready items (`order_items.ready_quantity − delivered_quantity > 0`, reservations present) + payment eligibility (`LedgerService::orderOutstanding` ≤ `deliveries.max_outstanding_for_pickup` setting, default 0 unless deposit-only pickup allowed per order flag) → returns a delivery draft (creates `deliveries` row in `in_progress` with idempotency key = sha256(scan token + operator + minute)? No: key = order + open delivery; one open delivery per order at a time (partial unique index on (order_id) where status in progress)).
- Confirm `POST /admin/deliveries/{delivery}/confirm` with items quantities: transaction, `lockForUpdate` on order_items and inventory reservations, validate qty ≤ ready − delivered, call `InventoryService::deliver(reservation, qty, reference delivery_item)`, update `order_items.delivered_quantity`, delivery status partial/completed, `OrderService::recalculateDelivery`, events, audit, Notify member (delivered/partial) — idempotent: the same confirmation (same idempotency key or already-completed delivery) returns the current state with 409/200 semantics (§278: a second device gets a clear conflict, never a duplicate). Manual override (deliver without QR) requires `deliveries.override` + reason → audit `deliveries.override`.
- Partial delivery keeps the order `partially_delivered`; remaining items stay ready; new delivery later (§277: 5 ready, 3 delivered → remaining 2).
- Authorized pickup: member creates an authorization (minimal data), receives a QR/code to hand over; verification at pickup, single use, logged.
- Event day: `EventRegistration::pickupOrders()` link; `/admin/events/{event}/operations` counters read deliveries (the Events engineer left hooks — implement `DeliveryStats::forEvent($event)` public service used there through class_exists).
- `deliveries:validate` command: delivered ≤ ordered, delivered ≤ ready, deliveries without movements, movements without delivery → OperationsExceptions (orders/inventory). Health check registered.
