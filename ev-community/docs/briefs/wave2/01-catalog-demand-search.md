## Rules
- SKU/part/OEM numbers are technical codes: exact-match search (case-insensitive, hyphen/space-insensitive on a normalized column `search_code` = uppercase alnum) that never alters the stored code; Arabic normalization (أ/إ/آ→ا, ة→ه, ى→ي, remove tashkeel) applied to a `search_text` column via a `SearchNormalizer` unit-tested class. `SearchService` (PostgreSQL ILIKE + `to_tsvector('simple')` GIN index, swappable via interface `SearchEngine` for Meilisearch later) with filters: vehicle (make/model/variant/year), category, brand, price range, availability, condition, compatibility status; sorting whitelist; pagination.
- `CompatibilityEngine::check(ProductVariant|Product, MemberVehicle|selection): CompatibilityResult(status verified|likely|needs_verification|not_compatible, reason, source)` — rule matching by make/model/(variant|year range)/market version/OEM match; unknown → needs_verification (never silently "compatible"); expose warnings for the UI.
- Price changes always write `product_price_history` (never overwrite silently); "market price" displayed only with source + date.
- Accepting a part-request quote creates an order via `App\Modules\Orders\Services\OrderFactory::fromPartRequestQuote($quote)` if that class exists (Orders module is built in parallel) — otherwise mark the quote accepted and raise a domain event `PartRequestQuoteAccepted` for the Orders module to consume; document it.
- Community demand report (admin): products with interest count, interested vehicle models, estimated quantity; "convert to group buy" link passes product ids to the group-buy create page (`/admin/group-buys/create?products=...`) — no automatic creation.

## Pages
- Public: `/{locale}/store` (grid/list, filters drawer on mobile, vehicle selector at top via `VehicleSelector`, compatibility badge per card relative to `selectedVehicle`), `/{locale}/store/{product:slug-or-public_id}` (gallery, variants, specs, compatibility panel with clear warnings, price history & reference prices with sources, add to cart button posting to `route('public.cart.add')` if the Cart module route exists else "notify me"/wishlist, warranty, related), `/{locale}/search?q=` (global search: products by name/SKU/OEM/part number + vehicles; members also see their order numbers), `/{locale}/categories/{slug}`, `/{locale}/brands/{slug}`, SEO meta (title/description/canonical/hreflang/OG) via a `Seo` prop convention documented for the CMS engineer.
- Member: `/account/wishlist` (items, notify when available / price drops toggles, move to cart), `/account/part-requests` (list, create with vehicle + photos, quotes with accept/decline), garage section `compatible_parts` (top compatible products for the vehicle).
- Admin: `/admin/products` (DataTable: search, filters status/availability/brand/category/compatibility-missing, bulk status/featured, export via Exporters), create/edit (bilingual fields, images upload via AttachmentService, variants matrix, specs, prices with history panel, compatibility rules editor using the vehicle master data, audit), `/admin/categories`, `/admin/brands`, `/admin/compatibility` (queue of items needing verification + bulk verify with source), `/admin/demand` (interest report, alerts stats, part requests with quote form), importers `ProductsImporter`, `PricesImporter`, `CompatibilityImporter` registered with the Imports framework, exporters `ProductsExporter`.
- Registrations: KPIs `products_active`, `products_out_of_stock` (admin); garage section `compatible_parts`; audiences none; health check "products with no price" and "variants with negative stock_cached".
