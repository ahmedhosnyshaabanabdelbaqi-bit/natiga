## Public website
- Homepage `/{locale}` built from `homepage_sections` order (admin-editable): premium hero (tagline from branding settings, CTA join/store, stats: members / stations / centers — computed live and cached 10 min), vehicle selector (`VehicleSelector` → store filtered), search parts, featured products (Catalog `Product::featured()` if module enabled), open group buys (`GroupBuy::open()` when table exists), maintenance offers (approved center quotes summary when available), charging stations (nearest verified or latest verified), partner offers, upcoming events, knowledge (latest articles), community CTA. Every section reads its data through a `HomepageSectionProvider` registry (`HomepageSections::register(key, fn(): array)`) so other modules register data providers; sections whose module is disabled or has no provider are skipped (never rendered empty/fake).
- Pages `/{locale}/pages/{slug}` (about, contact with form, privacy, terms — terms/privacy come from `policy_versions` latest published, rendered via the legal template with version + date), FAQ `/{locale}/faq`, contact form → contact_messages + Notify to support agents.
- SEO: `<Head>` per page with title/description/canonical/OG; `hreflang` alternates for ar/en (helper `seoAlternates(routeName, params)` in a shared PHP helper `App\Modules\Cms\Services\Seo`); JSON-LD Organization on home; `/sitemap.xml` (public routes for store products, categories, articles, stations, centers, events, pages — each module registers URL providers via `SitemapProviders::register`), `robots.txt` disallowing /admin, /partner, /account, /settings, /files; `noindex` on private pages (already in root template) — extend for auth pages.

## Reports (admin, permission reports.view / reports.export)
`/admin/reports` hub with date-filterable charts (Recharts; follow the dataviz palette + accessible color rules): orders over time, approved collections, outstanding receivables trend, popular vehicles (member_vehicles by model), top requested parts (interest + part requests), group-buy demand, inventory movement volume, maintenance bookings, support volume — each chart backed by a `ReportQuery` class returning `{series, source, generated_at}` and querying tables with `Schema::hasTable` guards (empty state when a module is disabled; never fake data). Reconciliation: report pages show totals with drill-down links to the filtered lists; the "reports total = Σ details" invariant is tested. Exports of any report via Exporters. Admin dashboard extras: register KPIs for Reports (`open_tickets` etc. already elsewhere — avoid duplicates), plus a personalised dashboard: `/admin/dashboard` already renders KPIs by permission; add role-oriented "quick actions" (links) computed by permission.
- Global admin search `GET /admin/search?q=` (permission-scoped across members (number/name/mobile), orders, receipts, payments references, shipments, packages, bookings, tickets, SKU/part numbers — each provider registered by modules via `AdminSearchProviders::register(key, permission, fn(q): array)`; you implement the registry + UI + providers for entities whose tables exist) and the command palette items provider (`CommandPaletteItems::register`) wired into the admin layout through a shared prop `commandPaletteItems` (Inertia::share from your provider; the integration pass mounts `CommandPalette` in the admin layout).
- Release/versioning: `config/version.php` (APP_VERSION, build ref, release date) shown in admin footer + `/admin/about`; `CHANGELOG.md` conventions documented.
