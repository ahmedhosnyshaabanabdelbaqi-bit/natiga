## Rules (BUSINESS_RULES §12)
- RFQ → invited centers submit quotes in the partner portal → admin compares only quotes of the same RFQ/service scope (comparison table: scope, price, parts brand, warranty, duration, capacity, branches; no cross-service comparison) → approve quotes (member-visible "maintenance offers"); quotes have validity; price snapshot copied into the booking (§282 test).
- Booking (`CreateBooking` action): member picks vehicle, service, center, branch, offer (approved quote) or center service price, date → available slots from `AvailabilityService::slots` → hold resources (`AvailabilityService::hold`) inside a transaction; capacity conflict → waiting list; hold expiry releases; confirm by center (or auto-confirm setting); statuses per contract with history + notifications (booking.requested/confirmed/reminder 24h/ready/completed); cancellation & no-show rules; reschedule = new hold + release.
- Check-in (partner): membership/booking QR (QrService purpose booking) or manual; record arrival, odometer, notes, condition photos (member consent checkbox stored) → work order created automatically.
- Work order: items, estimates; additional work request → member notification + approval page (`/account/maintenance/approvals/{request}`), decision stored with timestamp/amount; not approved → never counted in approved/final amounts (§281 test); completion (partner): installed parts, labor, final amount (must equal approved items unless override with reason → audit), odometer, technician notes, warranty, recommendations, next service (date/km) → `service_records` (verified) + `installed_parts` + reminders + Warranty via `Warranties::createFromServiceRecord` (class_exists) + report PDF (PdfService) + Notify; member-added records via `/account/maintenance/records/create` flagged member-added (never verified).
- Payment mode per booking snapshot (`pay_center` → platform records amounts for statlements? No: pay_center = no platform money; `pay_platform` → member pays via Payments module (order-like charge: use `LedgerService` "service charge" if Accounting exposes `charge(...)` for non-order sources — else create a lightweight `maintenance_charges` table and document); settlement per center per period: gross eligible completed pay_platform services + adjustments − platform fee (center's percent) − refunds − deductions = net; statuses draft → reviewed → approved → paid (payout recorded with reference; PDF); every settlement line traceable to a booking/work order; `settlements:reconcile` command verifies Σ items = totals → OperationsExceptions.
- Reminders: date or mileage (member updates odometer in the garage; reminder fires when due_km ≤ current odometer or date reached) via scheduled command + Notify (dedup); never claim automatic mileage.
- Center performance (admin, `CenterPerformance::metrics`): completed bookings, cancellation rate, no-show rate, average completion time, complaints count (Support tickets by center), verified review average (ReviewSummary), price deviation from approved quote (final vs snapshot), repeat visits — shown as indicators without ranking.
