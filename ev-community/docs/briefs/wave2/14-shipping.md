## Rules
- Status machine (ShipmentStatus enum with `canTransitionTo`), each transition writes `shipment_events` with `source = manual` (staff, audited) or `integration` (from `Integrations::shipping()->track()` / carrier webhook via `WebhookHandlers::register('shipping', …)`, idempotent by source_reference). The UI shows "live tracking" only when the carrier integration is configured — otherwise "manual updates" label (§42).
- Allocation: many orders → one shipment and one order → several shipments (`AllocationService::allocate(shipmentItem, orderItem, qty)` with row locks and the quantity invariant; updates `order_items.allocated_quantity`/`shipped_quantity` via `OrderService` public methods with class_exists guards). Receiving (`ReceiveShipmentItem`): records received/short/damaged/rejected, calls `InventoryService::receive` for accepted quantity into the target warehouse (idempotent by reference `shipment_item:{id}`), updates `order_items.received_quantity`, `PurchaseOrders::recordReceipt` when linked to a PO item; §276 split test: 6 received / 4 in transit shown per order.
- Documents private (HasAttachments: staff with shipments.view; members never see supplier documents); member-facing tracking shows only status/dates/location per shipment for their orders (`/account/orders/{order}` link → `/account/shipments/{shipment}` scoped to orders containing their items).
- Financial close (`shipments.close_financially`): blocks further expense allocation changes (Procurement checks `financially_closed_at`); shipment report PDF (items, allocations, expenses, landed cost summary).
- Delayed shipments (ETA passed, not arrived) → HealthChecks + OperationsExceptions (shipping, P2). Notify members on status changes of shipments containing their items (dedup per shipment+status+user).
