## Rules
- Every foreign-currency amount stores its FX snapshot via `ExchangeRates::convertToBase` at creation; later rate changes never touch it (test).
- PO lifecycle draft → pending_approval → approved (approver ≠ creator when `procurement.po_dual_approval_threshold` exceeded) → ordered → partially_received → received / cancelled; receiving updates come from the Shipping/Inventory modules through `PurchaseOrders::recordReceipt($poItem, $qty)` (public service method, idempotent by reference).
- Supplier payable = Σ invoices (base) − Σ payments − Σ credits; `procurement:reconcile-suppliers` command lists mismatches → OperationsExceptions (finance).
- Landed cost per shipment/PO: estimated vs final views; allocation must sum exactly to the expense (`Money::allocate`), rule stored with each allocation; re-allocation after "financial close" forbidden (DomainException).
- Supplier payments: maker/checker above `procurement.supplier_payment_dual_approval_threshold`; audit + security event on approval; attachments (invoice/receipt) private.
