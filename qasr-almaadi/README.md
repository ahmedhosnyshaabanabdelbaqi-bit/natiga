# Child — نظام إدارة المستشفى

نسخة العمل الحالية `2.0.2` توسّع نظام الحضّانات `1.1.2` إلى إدارة مستشفى بأقسام مترابطة وملف موحّد للمريض.
حزمة التحديث الموقّعة: `../output/child-update-2.0.2/child-2.0.2.nicu-update`. حالة التثبيت الفعلية موثقة في تقرير النشر المصاحب للحزمة.

الأقسام: الاستقبال والحجز، العيادات، الطوارئ والفرز، التنويم والعناية والحضّانات، العمليات، المعمل، الأشعة، الصيدلية، الحسابات والتأمين، المخزون والمشتريات، الموارد البشرية والصيانة. يمكن إضافة أقسام وتخصصات بأسماء المستشفى.
التحويل بين أقسام الرعاية يحتفظ بنفس الزيارة والطلبات والنتائج والفاتورة. ملف المريض يشمل البالغين والأطفال، مع إبقاء تفاصيل الحضّانات عند الحاجة.
التحديث من 1.1.2 يبدأ تلقائيًا بعد رفع الحزمة والتحقق منها، ثم النسخ الاحتياطي والتثبيت وفحص الصحة والرجوع عند الفشل وفق مسار المثبّت الحالي.
المصدر يستخدم React وTypeScript وNode.js 24، وقاعدة PGlite محلية أو PostgreSQL خارجي.

دليل التشغيل ونطاق التوسعة والاختبارات في [تقرير المستشفى 2.0](docs/HOSPITAL-2.0.md).
طريقة نقل الكود إلى سيرفر آخر في [دليل النشر](DEPLOY-ELSEWHERE.md).

## تشغيل نسخة جديدة

يتطلب Node.js 24 أو أحدث. نفّذ من هذا المجلد في PowerShell:

```powershell
npm.cmd ci
npm.cmd run build
$env:DATA_DIR = './data/local'
$env:HOSPITAL_NAME = 'اسم المستشفى'
$env:INITIAL_ADMIN_USERNAME = 'admin'
$setupSecret = Read-Host 'كلمة مرور الإدارة (16 حرفًا على الأقل)' -AsSecureString
$setupPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($setupSecret)
try {
  $env:INITIAL_ADMIN_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($setupPointer)
  npm.cmd run setup
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($setupPointer)
  Remove-Item Env:INITIAL_ADMIN_PASSWORD -ErrorAction SilentlyContinue
}
npm.cmd start
```

افتح `http://127.0.0.1:4310`. استخدم نفس `DATA_DIR` عند كل تشغيل.
أمر الإعداد يُنفّذ والخادم متوقف، وينشئ حساب إدارة واحدًا وإعدادات المستشفى فقط.
يرفض العمل إذا وُجد أي مستخدم، ولا ينشئ بيانات أطفال تجريبية أو يعيد ضبط الحسابات.
أضف الفريق والأسرة والأسعار من الواجهة بعد الدخول.

لو لم يكتمل الإعداد، تعرض صفحة الدخول رسالة الإعداد بدلًا من خطأ اتصال.
ملف `.env.example` مرجع للإعدادات؛ متغيراته لا تُحمّل تلقائيًا.

## قفل قاعدة البيانات واسترجاع التحديث

يفحص التشغيل والنسخ الاحتياطي قفل `.server-lock` داخل مجلد البيانات. يسترجع القفل تلقائيًا فقط إذا أثبت نظام التشغيل أن العملية المسجلة انتهت (`ESRCH`)، مع حارس حصري وإعادة فحص الملف. القفل الجديد يسجل PID واسم الجهاز ورمز ملكية فريدًا؛ الأقفال القديمة التي تحتوي PID فقط تظل مدعومة.

لا يُحذف قفل لعملية حية أو يتعذر التحقق منها، ولا ملف غير مفهوم أو متغير أثناء الفحص. إعادة استخدام PID بعد إعادة تشغيل الجهاز قد تؤدي إلى رفض محافظ يتطلب تحققًا يدويًا. الحارس `.server-lock-recovery` المتروك عند قتل العملية داخل الجزء المتزامن لا يُحذف تلقائيًا. لا تحذف أي قفل قبل التأكد من توقف كل مستخدمي قاعدة البيانات.

منسق التحديث المعدل يرجع للإصدار السابق أيضًا عند فشل أمر `systemctl start` نفسه، بالإضافة إلى فشل فحص الصحة. تحديث التطبيق لا يستبدل تلقائيًا المنسق المثبت بصلاحية root؛ طريقة ترقيته مع نسخة رجوع وفحص صياغة Bash موضحة في [دليل استرجاع التحديث](docs/UPDATE-RECOVERY.md).

## الفحص

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run check:browser
npm.cmd run check:roles
```

اختبارات الخادم والمتصفح تنشئ قواعد اختبار مستقلة ببيانات مصطنعة.
فحص المتصفح الأساسي يختبر الدخول والتسجيل والتسكين والقياسات وإعادة المحاولة والطباعة والعمل دون اتصال.
فحص الأدوار يشمل الأدوار الخمسة عشر والتنقل والعربية والإنجليزية والهاتف.
يتطلب فحص المتصفح Google Chrome مثبتًا ويعمل دون نافذة خارجية.

نتائج المراجعة وحدودها في [تقرير المراجعة](docs/SYSTEM-REVIEW.md).
النسخة الأصلية ومصدر الاختبارات موثّقان في التقرير.
