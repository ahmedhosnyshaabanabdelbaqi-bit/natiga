# مراجعة ترابط أقسام Child

13 سبتمبر 2026 — مراجعة نسخة العمل المحلية، ببيانات مصطنعة. لم تُعدّل قاعدة المستشفى ولم تُنشر التغييرات على السيرفر.

## الأخطاء الإضافية المثبتة والإصلاحات

| الاتصال بين الأقسام | الخطأ والإصلاح |
| --- | --- |
| المهام ← الأوامر ← توثيق التنفيذ | كان تعديل المهمة يسمح بإتمام مهمة أمر دون سجل تنفيذ أو تحقق هوية الطفل. أصبح التنفيذ من شاشة الأوامر، والخادم يرفض تجاوز هذا المسار. |
| استئناف الأوامر ← المهام | إعادة اعتماد/استئناف موعد منفذ كانت تنشئ مهمة معلقة لا يمكن إتمامها. يتحقق الإنشاء الآن من سجل التنفيذ الموجود. |
| الخروج ← التمريض والمهام والمعمل | كانت المهام اليدوية للإقامة تظل معلقة بعد إغلاقها. تُغلق المهام المعلقة والمؤجلة الخاصة بالإقامة؛ تبقى المهام العامة والمنجزة ونتائج المعمل المعلقة محفوظة. |
| المخزون والمستهلكات ← الفاتورة والدفتر المحاسبي | استبعاد حركات المخزون المرتبطة بالإقامة كان يخفي تكلفة الصرف. يظهر القيد الآن مرة واحدة مقابل نقص المخزون، مع بقاء إيراد فاتورة الطفل. |
| المشتريات ← دفعات المخزون | إعادة استخدام دفعة في أمر شراء كانت تخفي استلامات مستقلة على الدفعة نفسها من الحسابات. أضيف رابط مباشر بين حركة الاستلام وسطر الشراء في الترقية 022. |
| المشتريات ← الخزنة والدفتر | جمع القيم بعد تقريب كل سطر كان يختلف عن إجمالي الصرف الفعلي. وُحّد إجمالي القيد مع القيمة المحفوظة في أمر الشراء. |
| الموردون ← المحاسبة | إنشاء أو تعديل مورد بحد ائتماني صفري كان يُرفض رغم أن الصفر قيمة افتراضية مدعومة. أصبح الصفر مقبولًا. |
| الحضور ← الرواتب | إلغاء بصمة خروج أول الشهر لوردية بدأت الشهر السابق لم يُحدّث حالة مسير الشهر السابق. يُعلّم الآن المسير المتأثر لإعادة الحساب. |
| القيود اليدوية ← الخزنة والبنوك | سطور النقد كانت تغيّر دفتر اليومية دون رصيد حساب نقدي محدد. أضيف money_account_id في الترقية 023، واختيار الحساب بالواجهة، والتحقق من الرصيد عند الاعتماد والعكس، وترحيل الأثر إلى الحساب المختار. |
| التحويل الداخلي ← قائمة التدفقات النقدية | التحويل من الخزنة إلى البنك كان يضخّم إجمالي التدفقات الداخلة والخارجة. يُحسب الآن صافي النقدية لكل قيد، فلا يظهر التحويل الداخلي كتدفق خارجي. |
| إقفال الفترة ← المخزون والمستهلكات والأجهزة | بعض مسارات الصرف والاستلام المرتبطة بقيود مالية كانت تتجاوز إقفال الفترة. تدخل الآن في التحقق قبل الحفظ؛ يظل التوثيق الطبي غير المالي متاحًا. |
| اللوحة والمهام والمعمل ← ملف الطفل والإقامة | بعض الروابط لم تحمل patient_id أو فقدت admission_id، ففتحت قسمًا عامًا أو إقامة مختلفة. تُحفظ هوية الطفل والإقامة، ويفتح المعمل تبويب النتائج مباشرة. |
| حالات المهام ← الواجهة | عُدّلت حالة التأجيل لتطابق deferred، وأُزيلت إجراءات التعديل غير الصالحة للمهام الملغاة، ووُجّهت مهام الأوامر لتوثيق التنفيذ. |
| صلاحيات الإدارة ← واجهة القيود | تتبع أزرار اعتماد وعكس القيود الصلاحيات الفعلية التي يرسلها الخادم. |
| الشبكة ← القيود والسداد | كانت إعادة حفظ المسودة بعد ضياع رد ناجح تنشئ مفتاحًا جديدًا وتسمح بالتكرار. يُحفظ مفتاح نفس الطلب داخل المسودة وتُختبر إعادة الإرسال بعد حفظ الخادم وإسقاط الرد. |
| خريطة الأسرّة ← سرية بيانات الطفل | كان باركود الطفل يبقى ظاهرًا عند إخفاء باقي بياناته. يُحجب الآن أيضًا خارج الصلاحية أو التكليف، مع بقاء باركود السرير. |
| تغيير الدور ← إعادة المحاولة | رد عملية قديمة محفوظ كان قد يكشف حقولًا سريرية بعد تقليل صلاحيات المستخدم. يرتبط بصمة الطلب الآن بالدور والصلاحيات وطريقة الطلب. |
| تغيير التكليف ← إعادة المحاولة | الرد المحفوظ لتعديل بيانات الطفل لم يكن يعيد فحص التكليف الحالي. يُفحص قبل إرجاع الرد. |
| النسخة الاحتياطية ← الاستعادة ← إعادة التشغيل | القفل الموجود داخل النسخة المستعادة كان يمنع فتحها بواسطة الخادم. يُزال القفل الموروث بعد نجاح الاستعادة والتحقق وإغلاق القاعدة فقط، والاختبار يعيد فتح القاعدة ويتحقق من السجلات. |
| ترقية قاعدة قديمة ← التحديث الموقّع | تعديل بايتات 016 التاريخية كان سيُرفض بواسطة حماية التحديثات. أُبقي الملف التاريخي كما نُسخ من السيرفر، ويستخدم محمّل الترقية ملف SQL بديلًا آمنًا يضم إضافات المخطط دون المسح. الاختبار يثبت بصمة الملف التاريخي وإدراج البديل في حزمة التحديث وحفظ البيانات. |

## التعامل مع البيانات القديمة وحدود النتيجة

- الترقية 022 تربط حركة شراء قديمة فقط عند تطابق فريد ودقيق بين الحركة وسطر الأمر. السجلات الملتبسة تحتاج مراجعة مستنداتها، ولا تُخترع لها روابط.
- القيود النقدية التاريخية التي لم تسجّل حساب خزنة أو بنك تبقى غير مخصصة وتظهر بتحذير مستقل؛ لا يُنسب رصيدها تلقائيًا إلى حساب تخميني. لم تُراجع أرصدة أو مستندات التشغيل الحقيقية.
- تصحيح مسار المهام يمنع الحالات غير المتسقة مستقبلًا. لا يفترض أن مهمة قديمة قد نُفذت طبيًا؛ يحتاج تنظيف المهام القديمة إلى مراجعة سجلها الفعلي.
- مفاتيح إعادة المحاولة المحفوظة قبل تغيير بصمة الصلاحيات تعيد 409 بعد التحديث. تُراجع نتيجة العملية الأصلية قبل إنشاء طلب جديد؛ لا توجد إعادة تنفيذ آلية بمفتاح جديد.
- عند إقفال الشهر الحالي يجب إعادة فتحه بتفويض الإدارة لتسجيل حركة جديدة ذات أثر مالي؛ لا توجد آلية لترحيلها بتاريخ مؤجل.
- الفحوص محلية على Windows وNode.js 24 وPGlite. لم تشمل PostgreSQL خارجيًا، حجم الحمل الفعلي، أجهزة المستشفى، أو دورة systemd والتثبيت والرجوع على السيرفر.
- نجاح هذه الفحوص يعني عدم وجود فشل في الحالات المنفذة، وليس ضمانًا مطلقًا لغياب أي خطأ غير مكتشف.
