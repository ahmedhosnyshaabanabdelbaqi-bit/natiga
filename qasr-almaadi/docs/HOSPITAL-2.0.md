# تحويل النظام إلى إدارة مستشفى — 2.0.1

التاريخ: 27 سبتمبر 2026. ترحيلات قاعدة البيانات الجديدة: 024–027. إصدار الحزمة 2.0.1 وتسلسل التحديث 19. اختبارات العمليات تستخدم بيانات مصطنعة وقواعد مستقلة؛ حالة التثبيت الفعلية على السيرفر موثقة في تقرير النشر المصاحب للحزمة.

## رحلة المريض

1. يسجل الاستقبال ملف المريض بالاسم والميلاد والجنس والهوية والهاتف والعنوان. يمكن إنشاء الملف فقط للحجز لاحقًا، أو فتح زيارة مباشرة بالطوارئ أو العيادات أو التنويم أو العناية أو الحضّانات. رقم الهوية غير الفارغ فريد؛ رقم الملف ثابت لكل الزيارات.
2. حجز العيادة يربط المريض بالقسم والطبيب والوقت والمدة. يمنع تضارب مواعيد الطبيب والمريض. تسجيل الحضور ينشئ الزيارة مرة واحدة. إغلاق الموعد يتطلب انتهاء إجراءات الزيارة المرتبطة.
3. يحدد الفريق المختص درجة الفرز بالطوارئ. التحويل يربط نفس الزيارة بالقسم والسرير والفريق المستلم، ويسجل الحركة والسبب. السرير تابع لقسمه، ولا يمكن تسكين مريضين عليه. يظل تاريخ التحويل والطلبات والفاتورة مرتبطًا بالزيارة نفسها.
4. ملف المريض يجمع الأوامر والملاحظات والقياسات والتحاليل وتقارير الأشعة والعمليات والصرف والحساب والمرفقات والخروج. تبويب «الأقسام والخدمات» يعرض الخدمات وحركة المريض وروابط مباشرة للزيارة المحددة.
5. الأشعة: طلب ← موعد ← تنفيذ ← تقرير ← مراجعة الطبيب. العمليات: حجز الغرفة والجراح ← بدء ← إتمام بالتقرير ← مراجعة. يمنع تضارب حجز الغرفة أو الجراح. الطبيب الجراح المكلّف له وصول لنفس ملف العملية، وتُسحب هذه الصلاحية إذا ألغيت العملية ولم يكن مسؤول الرعاية.
6. الصيدلي يصرف من أمر دواء معتمد بعد مطابقة رقم ملف المريض واسم الصنف والتشغيلة والرصيد والصلاحية. تحفظ لقطة الأمر والتكلفة وحركة المخزون. الصرف مستقل عن توثيق إعطاء الجرعة بواسطة التمريض.
7. اختيار سعر خدمة يضيفه للحساب مرة واحدة عند تنفيذ الأشعة أو إكمال العملية أو الصرف. السعر والكمية والقيمة محفوظة وقت التنفيذ. لا تضيف الطلبات المكررة نفس التكلفة مرتين، وتمنع الفترة المقفلة الحركات المالية الجديدة.
8. الخروج يتبع مسار الحسابات الحالي وتسوية المستحق. لا يمكن إنهاء الخروج أثناء عملية جراحية جارية. تلغى الخدمات المجدولة التي لم تُنفذ مع أثر تدقيق، وتظل تقارير الأشعة المنفذة قابلة للاستكمال والمراجعة.
9. لكل قسم مركز تكلفة مرتبط به. القيود تربط الخدمة بقسم المريض وقت تسجيل الحركة؛ تغيير قسم المريض لاحقًا لا ينقل الإيرادات القديمة إلى القسم الجديد. رسوم المعمل تُضاف صراحة إلى حساب الزيارة من الحسابات؛ توثيق النتيجة وحده لا يضيف رسمًا تلقائيًا.

## الإعداد على المستشفى

- من «الأقسام والتخصصات» أضف العيادات والتخصصات والأقسام بأسمائها الفعلية، مثل الباطنة والجراحة والعظام، وحدد نوع كل قسم.
- أضف الأسرة واربط كل سرير بقسمه. الأسرّة والزيارات السابقة تُنسب تلقائيًا للحضّانات، دون إعادة إنشاء الملفات أو تغيير أرقامها.
- أنشئ حسابات الموظفين وحدد الأدوار، ومنها الدوران الجديدان «طبيب الأشعة» و«صيدلي». لا ينشئ التحديث كلمات مرور أو مستخدمين جدد في بيئة التشغيل.
- جهز قائمة الخدمات وأسعارها وتشغيلات الأدوية. لا تُخمن جرعات أو بدائل دوائية، ولا يفترض النظام سعرًا لخدمة غير مسعّرة.
- بيانات القياسات القديمة والجديدة تحفظ الوزن بالجرام للمحافظة على اتساق التاريخ، ويظهر اسم الوحدة في الإدخال. أضيف الضغط الانقباضي والانبساطي والطول ودرجة الألم للبالغين والأطفال.

## حفظ البيانات والصلاحيات

الترحيلات إضافية؛ ملفات الترحيل 001–023 محفوظة دون تعديل. لا تنقل الحزمة قاعدة بيانات أو أسرارًا أو بيانات مرضى. تستمر الحضّانات والتغذية واللبن والباركود والمحاسبة والتأمين والمشتريات والحضور في النظام نفسه.

زيارة رعاية نشطة واحدة لكل مريض مقصودة في هذا الإصدار: استخدم التحويل عند الانتقال بين الأقسام بدل فتح زيارة متزامنة ثانية. بعد الخروج يمكن فتح زيارة جديدة بنفس ملف المريض.

صلاحيات الأطباء والتمريض مرتبطة بتكليفهم بالحالة، وتضاف صلاحية الحالة للجراح المعيّن صراحة. الأشعة والصيدلية لهما أدوار محددة. الإسقاطات غير السريرية تخفي التشخيص والملاحظات الطبية والفرز. تعيد الطلبات المكررة فحص الصلاحيات، وتحمي أرقام إصدارات السجلات من الكتابة على بيانات تغيرت.

## ما تم فحصه

- رحلة API كاملة: ملف جديد ← موعد وحضور ← طوارئ وفرز ← تحويل وتسكين وتكليف الفريق ← علاج ومعمل وأشعة وصيدلية وعمليات ← دفعتان وتسوية الحساب ← خروج وتجهيز السرير ← زيارة جديدة بنفس الملف. ست رسوم بمجموع 2,151.50 جنيه، وسداد كامل دون تكرار الرسوم أو صرف الدواء، وقيود متوازنة.
- استرجاع قفل عملية انتهت مع رفض الأقفال الحية أو غير المؤكدة، ومنع التنافس بين عمليات فتح القاعدة. فشل بدء الخدمة الجديدة ينتقل لمسار الرجوع في منسق التحديث. راجع [دليل الرجوع](UPDATE-RECOVERY.md).
- مجموعة الاختبارات الكاملة: 164 اختبارًا ناجحًا قبل التحسين النهائي لنطاق وصول الجراح.
- بعد ربط الجراح بالملف: 25 اختبارًا مستهدفًا ناجحًا تشمل الخدمات والصلاحيات وتغيّر التكليف والرعاية والخروج.
- التنقل: 15 دورًا و207 زيارات للصفحات، دون استجابات API مرفوضة أو استثناءات JavaScript.
- رحلة متصفح فعلية بأربعة أدوار: تسجيل بالغ ← موعد ← حضور وملف الزيارة ← أشعة وتقرير ومراجعة ← صرف دواء ورصيد وفاتورة ← عملية وتقرير ومراجعة.
- عرض الصفحات الجديدة التسع بعرض هاتف 390 بكسل، وفحص صور للشاشات.
- ترقية بيانات قديمة إلى البنية الجديدة، وحفظ السجلات وأرقام الملفات والفواتير والأسرة، ورفض تضارب المواعيد والأسرة والصرف المكرر.
- بناء TypeScript وواجهة الإنتاج، والتحقق من توقيع حزمة الإصدار وتسلسلها وتطابق الترحيلات السابقة.

الفحص ببيانات مصطنعة وقواعد مستقلة. تكامل الأجهزة الفعلي وPACS/DICOM وواجهات أجهزة المعمل والربط الخارجي مع التأمين غير مضاف في هذه التوسعة؛ المعمل والأشعة هنا مسارات طلب وتوثيق ومراجعة داخل النظام. لا تُستخدم بيانات مرضى وهمية داخل سيرفر التشغيل لاختبار الحركات المالية أو الطبية.
