# دليل تشغيل EV Car News على السيرفر (خطوة بخطوة)

الدليل ده معمول لحد مش متخصص. هتنفذ الخطوات بالترتيب، وكل أمر مكتوب زي ما هو تنسخه وتلصقه.
النسخة الإنجليزية المختصرة (فيها التفاصيل التقنية): [`DEPLOYMENT.md`](DEPLOYMENT.md).

**النتيجة في الآخر:**

| الحاجة | العنوان |
|---|---|
| الـ API (اللي التطبيق بيكلمه) | `https://api.evcar.news/api/v1` |
| لوحة التحكم (إضافة أخبار وسيارات ومحطات) | `https://admin.evcar.news` |
| الصور وملفات 360° | `https://api.evcar.news/media/...` |
| موقعك الحالي | `https://evcar.news` — **مش هيتلمس خالص** |

---

## 0) قبل ما تبدأ: هتحتاج إيه؟

- **السيرفر (VPS)** اللي عندك، بنظام **Ubuntu 22.04 أو 24.04**، وتقدر تدخل عليه بـ `root` أو بمستخدم عنده `sudo`.
- **الدومين evcar.news** (عندك). هنضيف له "دومين فرعي" (subdomain) جديد اسمه `api` وواحد اسمه `admin`.
- **مش محتاج تشتري أي حاجة زيادة.** شهادة HTTPS مجانية (Let's Encrypt) وكل البرامج مفتوحة المصدر.
- مواصفات مقترحة للسيرفر: **2 GB رام على الأقل (4 GB أحسن)**، 2 معالج، و **40 GB مساحة** فاضية أو أكتر (صور الـ 360° بتاخد مساحة).
  لو الرام أقل من 2 GB السكربت بيعمل swap تلقائي، بس أول تشغيل هيبقى بطيء.
- يفضّل السيرفر يكون معالج **amd64** (أغلب السيرفرات كده). لو arm64 السكربت هيشتغل برضه وهيقولك إنه استخدم نسخة بديلة من قاعدة البيانات.

> ملحوظة مهمة: لو موقع evcar.news شغال **على نفس السيرفر** (nginx أو Apache)، السكربت هيكتشف ده لوحده
> ومش هياخد مكان الموقع. هيضيف ملف إعداد **جديد** خاص بـ `api.evcar.news` بس (تفاصيل في الخطوة 4).

## 1) سجلات الـ DNS (اعملها الأول)

ادخل على المكان اللي بتدير منه الدومين evcar.news (زي Cloudflare أو Namecheap أو GoDaddy أو شركة الاستضافة)، وافتح صفحة **DNS**.

1. اعرف رقم الـ IP بتاع السيرفر (من لوحة شركة السيرفر، أو اكتب على السيرفر: `curl -4 ifconfig.me`).
2. **أضف** السجلين دول (متعدلش ولا تمسح أي سجل موجود):

| النوع (Type) | الاسم (Name/Host) | القيمة (Value) |
|---|---|---|
| `A` | `api` | IP السيرفر (مثال `203.0.113.10`) |
| `A` | `admin` | نفس IP السيرفر |

3. **متلمسش** سجلات `evcar.news` أو `www` أو سجلات الإيميل (MX) — دي بتاعة الموقع الحالي.
4. لو بتستخدم **Cloudflare**: خلّي السحابة **رمادي (DNS only)** للسجلين الجداد. (البرتقالي بيعطّل إصدار الشهادة الأول ويخلّي عنوان الـ IP الحقيقي للزوار غلط).
5. سجل `AAAA` (IPv6): **متضيفوش** إلا لو متأكد إن السيرفر عنده IPv6 وإنك كاتب العنوان الصح. سجل AAAA غلط بيبوّظ إصدار الشهادة.

تقدر تتأكد من جهازك (ممكن ياخد من دقايق لساعات):

```bash
nslookup api.evcar.news
```

لازم يطلع IP السيرفر. وبعد التثبيت فيه أمر جاهز: `sudo evcar dns-check`.

## 2) ادخل على السيرفر بـ SSH

- **ويندوز:** افتح PowerShell واكتب:
  ```bash
  ssh root@IP-السيرفر
  ```
- **ماك / لينكس:** افتح Terminal واكتب نفس الأمر.
- لو بتدخل بمستخدم عادي عنده sudo، استخدم اسمه بدل `root` (والأوامر اللي فيها `sudo` هتطلب كلمة سره).

## 3) شغّل أمر التثبيت

انسخ السطرين دول مع بعض:

```bash
curl -fsSL https://raw.githubusercontent.com/ahmedhosnyshaabanabdelbaqi-bit/natiga/claude/eager-ride-uhdmax/evcar-news/deploy/install.sh -o install.sh
sudo bash install.sh --branch claude/eager-ride-uhdmax
```

> **الفرع (branch):** الكود حاليًا في الفرع `claude/eager-ride-uhdmax`. أول ما يتدمج في `main`
> استبدل الاسم في السطرين بـ `main` (في الرابط وفي `--branch`).

عايز تشوف السكربت هيعمل إيه **من غير ما يغيّر أي حاجة**؟ شغّله الأول بـ `--dry-run`:

```bash
sudo bash install.sh --branch claude/eager-ride-uhdmax --dry-run
```

تقدر تشغّل السكربت أكتر من مرة بأمان: اللي اتعمل قبل كده بيتخطاه، والأسرار (كلمات السر) **مبتتغيرش** أبدًا.

## 4) جاوب على الأسئلة

السكربت هيسألك شوية أسئلة. لو القيمة اللي بين `[ ]` مناسبة دوس **Enter** بس:

| السؤال | تكتب إيه |
|---|---|
| `API domain` | Enter (يعني `api.evcar.news`) |
| `Admin panel domain` | Enter (يعني `admin.evcar.news`)، أو اكتب `none` لو مش عايز لوحة تحكم دلوقتي |
| `Administrator e-mail` | إيميلك (بيتسجل في Let's Encrypt وبتوصل عليه التنبيهات) |
| `Configure an SMTP server now?` | `y` لو عندك بيانات سيرفر إيميل، أو Enter (لا) وتظبطه بعدين — شوف قسم "الإيميل" |
| `Open Charge Map API key` | Enter للتخطي (مفتاح اختياري لاستيراد محطات الشحن) |
| `Continue?` | Enter (نعم) |

بعد كده السكربت هيشتغل لوحده (من 10 لـ 25 دقيقة أول مرة)، وبيعمل:

1. يتأكد من نسخة Ubuntu والرام والمساحة.
2. يسطّب **Docker** من موقع Docker الرسمي (ولو Docker متسطّب قبل كده بيسيبه زي ما هو).
3. يعمل مستخدم نظام اسمه `evcar` وفولدر `/opt/evcar`.
4. يفعّل **الجدار الناري UFW** (يسمح بـ SSH و 80 و 443 بس)، و **fail2ban** ضد تخمين كلمة سر SSH، و**التحديثات الأمنية التلقائية**، و swap لو الرام صغيرة.
   لو فيه برامج تانية على السيرفر فاتحة بورتات للإنترنت، هيسألك قبل ما يفعّل الجدار (عشان ميقفلهاش).
5. ينزّل الكود في `/opt/evcar/app`.
6. يعمل ملف الإعدادات `/opt/evcar/.env.production` فيه **كلمات سر عشوائية قوية** (محدش يعرفها، ومبتظهرش على الشاشة).
7. يجهّز النسخ الاحتياطي اليومي، واختبار الاستعادة الأسبوعي، والمراقبة كل 5 دقايق.
8. يبني البرنامج ويشغّله.

### لو السيرفر عليه الموقع الحالي (nginx أو Apache على البورت 80/443)

هتشوف رسالة زي: `nginx already serves ports 80/443 (your existing site)`. ده معناه:

- الـ API هيشتغل داخليًا بس على `127.0.0.1:3000` (مش ظاهر للإنترنت).
- السكربت هيسألك: **`Install the vhost now?`** → اكتب `y`.
  ده بيضيف **ملف جديد منفصل** اسمه `evcar-news.conf` خاص بـ `api.evcar.news` و `admin.evcar.news` بس،
  وبيختبر الإعدادات (`nginx -t`) قبل ما يعمل reload. **لو الاختبار فشل بيرجّع كل حاجة زي ما كانت** والموقع الحالي بيفضل شغال.
  ملف موقعك الحالي **مش بيتفتح ولا بيتعدل**.
- لو الـ DNS جاهز هيسألك: **`Request the Let's Encrypt certificate now (certbot)?`** → `y`.
  لو الـ DNS لسه مش جاهز، استنى وبعدين نفّذ:
  ```bash
  sudo evcar dns-check
  sudo evcar proxy-setup --install --cert
  ```

لو السيرفر فاضي (البورت 80/443 مش مستخدم)، السكربت بيستخدم **Caddy** اللي بيطلع شهادة HTTPS **لوحده** أول ما الـ DNS يكون صح.
لو الـ DNS كان لسه مش جاهز وقت التثبيت، بعد ما يجهز نفّذ: `sudo evcar restart caddy`.

## 5) اعمل حساب المالك (Owner) — أول مدير

```bash
sudo evcar create-owner --email you@example.com --name "اسمك"
```

هيطبعلك **رابط يستخدم مرة واحدة** (صالح 24 ساعة) شكله كده:
`https://admin.evcar.news/setup-password?token=...`

- افتحه في المتصفح، اختار كلمة السر، وبعدها ادخل على `https://admin.evcar.news` بالإيميل وكلمة السر.
- الرابط **مبيتحفظش** في أي مكان، ولو ضاع أو انتهى نفّذ الأمر تاني (بيطلع رابط جديد).
- لو اخترت ميبقاش فيه لوحة تحكم (`none`)، اختار كلمة السر من السيرفر مباشرة:
  ```bash
  sudo evcar create-owner --email you@example.com --set-password
  ```

**مفيش أي كلمة سر ثابتة في الكود.** كل مدير بيختار كلمة سره بنفسه.

## 7) ربط تطبيق الموبايل (APK) بالسيرفر

التطبيق أصلًا متظبط على `https://api.evcar.news/api/v1`. لو غيرت اسم الدومين، أو عايز تتأكد:

1. افتح المستودع على GitHub → **Settings** → **Secrets and variables** → **Actions** → تبويب **Variables** → **New repository variable**:
   - Name: `EVCAR_API_BASE_URL`
   - Value: `https://api.evcar.news/api/v1`
2. روح **Actions** → اختار **evcar-android** → **Run workflow** → اختار الفرع → **Run workflow**.
3. بعد ما يخلص (حوالي 15–25 دقيقة) هتلاقي نسخة جديدة في **Releases** باسم `android-test-رقم`:
   نزّل `evcar-news-arm64.apk` (لأغلب الموبايلات) أو `evcar-news-universal.apk`.
4. النسخة دي للتجربة (موقّعة بمفتاح debug): امسح النسخة القديمة من الموبايل قبل ما تسطّب الجديدة.

## الإيميل (SMTP) — مهم للمستخدمين

الـ API بيبعت إيميلات (تفعيل الحساب، نسيت كلمة السر). **من غير SMTP السيرفر بيشتغل عادي**،
بس الإيميلات **مش بتوصل لحد**: بتتحفظ في "صندوق صادر محلي" تقدر تشوفه:

```bash
sudo evcar mail-outbox
```

عشان الإيميلات توصل فعلًا، محتاج حساب SMTP. أمثلة (راجع شروط وخطط كل مزود، إحنا مش بنفترض أسعار):

- **Gmail**: فعّل التحقق بخطوتين، واعمل "App password"، واستخدم `smtp.gmail.com` بورت `587`. (فيه حدود يومية لعدد الرسايل).
- مزود إيميلات معاملات (Transactional) — بعضهم عنده خطة مجانية محدودة.
- سيرفر الإيميل بتاع الاستضافة لو عندك.

وبعدين:

```bash
sudo evcar set SMTP_HOST=smtp.gmail.com
sudo evcar set SMTP_PORT=587
sudo evcar set SMTP_USER=you@gmail.com
sudo evcar set SMTP_PASSWORD='app-password-here'
sudo evcar set MAIL_FROM='EV Car News <you@gmail.com>'
sudo evcar up
```

(للبورت 465 زوّد: `sudo evcar set SMTP_SECURE=true`.)

## التحديث (لما يبقى فيه كود جديد)

```bash
sudo evcar update
```

بيعمل بالترتيب: يسحب الكود الجديد ← يبني النسخة الجديدة والقديمة لسه شغالة ← **نسخة احتياطية لقاعدة البيانات** ←
يطبّق تحديثات قاعدة البيانات ← يعيد التشغيل. التوقف بيبقى ثواني (في وضع Caddy الطلبات بتستنى الـ API لحد 30 ثانية بدل ما تطلع خطأ؛ في وضع nginx/Apache ممكن تظهر رسالة خطأ لثواني).

- تغيير الفرع: `sudo evcar update --branch main`
- لو حصلت مشكلة بعد التحديث: `sudo evcar rollback` (بيرجّع النسخة اللي قبلها).
  لو التحديث غيّر في قاعدة البيانات بشكل مش متوافق، استرجع النسخة اللي اتعملت قبل التحديث (`sudo evcar backups` هتلاقيها باسم `pre-update`).

## النسخ الاحتياطي والاستعادة

**تلقائي:** كل يوم الساعة 03:15 بتوقيت UTC (يعني 5:15 أو 6:15 الصبح بتوقيت القاهرة) بيتعمل نسخة من:
قاعدة البيانات (`pg_dump`) + كل الصور وملفات 360°. بيتحفظ **آخر 7 أيام + آخر 4 أسابيع** في `/opt/evcar/backups`.

**اختبار استعادة تلقائي** كل يوم حد: بيسترجع آخر نسخة في قاعدة بيانات مؤقتة، ويعدّ الصفوف في كل جدول،
ويقارنها بالنسخة، ولو فيه أي اختلاف بيبعتلك تنبيه. (ده المطلوب في المتطلبات: "اختبار استعادة").

| عايز تعمل إيه | الأمر |
|---|---|
| نسخة دلوقتي | `sudo evcar backup` |
| تشوف النسخ | `sudo evcar backups` |
| تختبر آخر نسخة | `sudo evcar restore-test` |
| تسترجع آخر نسخة | `sudo evcar restore latest` |
| تسترجع نسخة معينة | `sudo evcar restore 20260925T031500Z` |
| قاعدة البيانات بس | `sudo evcar restore latest --db-only` |

الاستعادة **آمنة**: بتطلب منك تكتب `RESTORE`، وبتعمل نسخة من الوضع الحالي الأول، وبتسترجع في قاعدة بيانات
جديدة وتتأكد منها **قبل** ما تبدّل. القاعدة القديمة بتفضل موجودة باسم `..._pre_restore_...` لحد ما تمسحها بنفسك
(الأمر بيتكتبلك في الآخر).

### نسخة برّه السيرفر (موصى بيها جدًا)

لو السيرفر نفسه باظ، النسخ اللي عليه هتضيع معاه. اعمل نسخة خارجية (أي تخزين S3 متوافق، Backblaze B2،
Google Drive، أو سيرفر تاني بـ SFTP):

```bash
sudo evcar offsite-setup
```

بيسطّب `rclone` ويسألك عن مزود التخزين. **نصيحة:** اعمل remote من نوع `crypt` فوقه عشان النسخ تتشفّر قبل ما تخرج من السيرفر.
بعدها كل نسخة يومية وأسبوعية بتترفع لوحدها.

### احتفظ بملف الإعدادات

```bash
sudo cat /opt/evcar/.env.production
```

انسخه واحفظه في مدير كلمات سر (Password manager). **متبعتوش** على إيميل أو واتساب.

### الاسترجاع على سيرفر جديد (لو القديم ضاع)

1. جهّز السيرفر الجديد وشغّل `install.sh` زي الخطوة 3 (هيعمل كلمات سر جديدة، وده طبيعي).
2. انقل فولدر النسخة (مثلًا من التخزين الخارجي بـ rclone) إلى `/opt/evcar/backups/manual/`.
3. `sudo evcar restore <اسم-النسخة>`.
4. غيّر سجلات الـ DNS للـ IP الجديد.

## المراقبة والتنبيهات

كل 5 دقايق السيرفر بيفحص: الخدمات شغالة؟ الـ API سليم؟ الرابط `https://api.evcar.news` شغال؟ المساحة قربت تخلص (أكتر من 85%)؟
فيه خدمة بتقع وتقوم (restart) أو الرام خلصت؟ آخر نسخة احتياطية أقدم من يوم؟ اختبار الاستعادة فشل؟ الشهادة قربت تنتهي؟

**التنبيهات بتوصلك على:**

- **الإيميل** (`ALERT_EMAIL`) — لازم SMTP يكون متظبط.
- **Webhook** (تيليجرام / ديسكورد / سلاك...). مثال تيليجرام: اعمل بوت من `@BotFather`، هات `chat_id` بتاعك، وبعدين:
  ```bash
  sudo evcar set ALERT_WEBHOOK_URL='https://api.telegram.org/bot<TOKEN>/sendMessage?chat_id=<CHAT_ID>'
  ```
- (اختياري) رابط "نبض" `MONITOR_HEARTBEAT_URL` من خدمة مراقبة خارجية: لو السيرفر كله وقع، الخدمة الخارجية هي اللي هتنبهك.

تشغيل الفحص يدوي: `sudo evcar monitor`. السجلات: `journalctl -u evcar-monitor -n 50`.

## حل المشاكل

### "البورت 80 أو 443 مشغول"
ده غالبًا الموقع الحالي (nginx/Apache). السكربت بيتعامل معاه لوحده (الخطوة 4). لو برنامج تاني (Traefik، Caddy تاني، حاوية Docker تانية)
هيختار وضع `external` ويطبعلك المطلوب: `sudo evcar proxy-config`.

### الـ DNS لسه مش شغال
```bash
sudo evcar dns-check
```
لو طلع إن السجل مش موجود أو بيشاور على IP تاني: راجع صفحة DNS. التغيير ممكن ياخد لحد كام ساعة.
بعد ما يظبط: `sudo evcar restart caddy` (أو `sudo evcar proxy-setup --install --cert` في وضع nginx/Apache).

### خطأ في الشهادة (HTTPS)
- `sudo evcar logs caddy` وشوف الرسالة.
- أشهر الأسباب: سجل AAAA غلط، Cloudflare برتقالي بدل رمادي، الـ DNS لسه مش واصل، أو محاولات كتير فاشلة (Let's Encrypt بيوقف مؤقتًا — استنى ساعة).
- في وضع nginx/Apache: `sudo certbot certificates` و `sudo evcar proxy-setup --install --cert`.

### الرام خلصت (Out of memory) أو البناء بيقف
- `sudo evcar status` هيقولك لو خدمة اتقفلت بسبب الرام.
- شغّل الـ worker جوه الـ API بدل حاوية منفصلة: `sudo evcar set EVCAR_WORKER_MODE=combined` ثم `sudo evcar up`.
- لو الرام 1 GB: الأحسن ترقّي السيرفر لـ 2–4 GB. الـ swap بيساعد بس بيبطّأ.

### الـ API مش راضي يشتغل
```bash
sudo evcar logs api
```
لو فيه سطر فيه `Invalid environment configuration` هيقولك بالظبط أنهي إعداد ناقص في `/opt/evcar/.env.production`.

### بناء لوحة التحكم فشل
تقدر تشغّل الـ API لوحده لحد ما تتصلح: `sudo evcar set ADMIN_DOMAIN=` ثم `sudo evcar up`.

### المساحة قربت تخلص
- `sudo evcar status` (المساحة وحجم النسخ).
- قلّل عدد النسخ: `sudo evcar set BACKUP_KEEP_DAILY=3`.
- امسح القاعدة القديمة بعد استعادة: الأمر اللي اتكتبلك وقتها.
- `docker system df` يوضح مساحة Docker.

### نسيت كلمة سر المالك
`sudo evcar create-owner --email نفس-الإيميل` بيطلع رابط جديد لتغيير كلمة السر.

## قائمة الأمان (Checklist)

- [ ] ادخل على SSH بـ **مفتاح (SSH key)** مش بكلمة سر، وبعد ما تتأكد إن المفتاح شغال اقفل الدخول بكلمة سر
      (`PasswordAuthentication no` في `/etc/ssh/sshd_config` ثم `sudo systemctl restart ssh`) — **خلي نافذة SSH مفتوحة وانت بتجرب**.
- [ ] الجدار الناري شغال: `sudo ufw status` (SSH و 80 و 443 بس).
- [ ] `sudo fail2ban-client status sshd` شغال.
- [ ] ملف `/opt/evcar/.env.production` صلاحياته `600` ومحفوظ نسخة منه في مدير كلمات سر.
- [ ] قاعدة البيانات و Redis **مش** ظاهرين للإنترنت (`sudo evcar status` بيتأكد من البورتات).
- [ ] النسخ الخارجية شغالة ومشفّرة (`sudo evcar offsite-setup`).
- [ ] التنبيهات بتوصلك (جرّب: `sudo evcar monitor`).
- [ ] فعّل التحقق بخطوتين (2FA) على GitHub ولوحة الدومين وحساب السيرفر.
- [ ] أعد تشغيل السيرفر كل فترة لما تحديثات الكيرنل تنزل (`/var/run/reboot-required` موجود) — في وقت الزحمة فيه قليلة.
- [ ] عدد المديرين في لوحة التحكم قليل، وكل واحد بصلاحيات على قد شغله.
- [ ] **ممنوع** بيانات تجريبية (demo) على السيرفر الحقيقي — الأمر `sudo evcar seed --demo` بيرفض أصلًا.

## إيه اللي ممكن يكلّف فلوس؟

- **الإجباري: مفيش حاجة غير السيرفر والدومين اللي عندك أصلًا.** Docker و PostgreSQL و Redis و Caddy وشهادات Let's Encrypt كلها مجانية.
- **اختياري حسب احتياجك** (الأسعار بتتغير — راجع موقع كل مزود، إحنا مش بنكتب أسعار):
  - مزود إيميل SMTP (فيه خيارات مجانية بحدود).
  - تخزين خارجي للنسخ الاحتياطية.
  - تخزين صور S3 أو CDN لو الصور كترت جدًا.
  - مزودي الخرائط والمسارات: الخرائط الافتراضية من OpenStreetMap ليها **سياسة استخدام** للسيرفرات العامة؛ لو التطبيق بقى عليه استخدام كبير
    هتحتاج مزود خرائط (ممكن يبقى مدفوع). حساب المسارات (OpenRouteService / سيرفر OSRM خاص) اختياري، وGoogle Routes مقفول عمدًا (شروط الترخيص).
  - Open Charge Map: مفتاح الـ API بالتسجيل، وبشروط ترخيص البيانات بتاعتهم.
  - تكبير السيرفر (رام/مساحة) لما الاستخدام يزيد.

## كل الأوامر في مكان واحد

| الأمر | بيعمل إيه |
|---|---|
| `sudo evcar status` | حالة كل حاجة |
| `sudo evcar health` | فحص الـ API |
| `sudo evcar logs api -f` | سجلات الـ API مباشرة (Ctrl+C للخروج) |
| `sudo evcar up` | تشغيل / تطبيق تعديل في الإعدادات |
| `sudo evcar down` | إيقاف (البيانات بتفضل موجودة) |
| `sudo evcar restart caddy` | إعادة تشغيل خدمة |
| `sudo evcar update` | تحديث الكود |
| `sudo evcar rollback` | الرجوع للنسخة اللي قبلها |
| `sudo evcar create-owner --email ...` | أول مدير / رابط كلمة سر جديد |
| `sudo evcar backup` / `backups` / `restore` / `restore-test` | النسخ الاحتياطي |
| `sudo evcar set KEY=VALUE` | تغيير إعداد (وبعده `sudo evcar up`) |
| `sudo evcar dns-check` | فحص الـ DNS |
| `sudo evcar mail-outbox` | الإيميلات المحفوظة لو SMTP مش متظبط |
| `sudo evcar help` | كل الأوامر |

## الملفات المهمة

| المسار | إيه ده |
|---|---|
| `/opt/evcar/.env.production` | الإعدادات وكلمات السر (سري، صلاحية 600) |
| `/opt/evcar/app/evcar-news` | الكود |
| `/opt/evcar/backups` | النسخ الاحتياطية (daily / weekly / manual / pre-update / pre-restore) |
| `/opt/evcar/state` | حالة آخر نسخة واختبار استعادة ومراقبة |
| `/opt/evcar/proxy` | ملفات nginx/Apache اللي اتولّدت (في وضع السيرفر الموجود) |
