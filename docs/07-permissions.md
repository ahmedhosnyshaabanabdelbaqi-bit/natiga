# الصلاحيات والنطاقات

## 1. المبدأ

**الرفض الافتراضي.** كل مسار API يعلن الصلاحية التي يحتاجها، والوسيط يرفض أي
مسار لا يعلن صلاحية — فنسيان الإعلان يعطي 403 ولا يفتح بابًا.

إخفاء زر أو عمود في الواجهة ليس صلاحية. التكلفة والربح **يُحذفان من الاستجابة
نفسها** لمن لا يملك صلاحيتهما، لا يُخفيان في العرض.

## 2. ثلاث طبقات

| الطبقة | ما تحكمه |
|---|---|
| **الصلاحية** | هل يُسمح بالعملية أصلًا (`sales.invoice.post`) |
| **النطاق** | أي فروع/مخازن/مناطق يصلها المستخدم (`user_scopes`) |
| **الإسناد** | أي عملاء يخص هذا المندوب (`customer_assignments`) |

النطاق الفارغ يعني «بلا تقييد داخل الشركة» — التقييد اختياري يضبطه المسؤول.

المندوب بدون `customers.view.all` يرى عملاءه المسندين فقط، والتقييد مطبق على
الاستعلام نفسه، فتغيير معرف في الرابط لا يفتح عميل زميله. مُثبت باختبار.

## 3. فصل متعمد

| العملية | صلاحية منفصلة لأن |
|---|---|
| إنشاء فاتورة / ترحيلها | المندوب يُصدر، المحاسب يُرحّل |
| استلام مرتجع / اعتماده ماليًا | الاستلام فعل مخزني، الاعتماد قرار مالي |
| إنشاء تسوية / اعتمادها | لا يعتمد أحد تسوية أنشأها بنفسه |
| عرض بياناتي / عرض الكل | `.view` مقابل `.view.all` |
| رؤية التكلفة والربح | `inventory.cost.view`, `reports.profit.view` |
| تعديل السعر يدويًا | `sales.price.override` |
| منح خصم | `sales.discount.override` |
| تجاوز الحد الائتماني | `sales.credit.override` |
| الإقفال قبل اكتمال المزامنة | `field.day_closing.sync_override` |
| إعادة فتح يوم مقفل | `field.day_closing.reopen` |

## 4. الأدوار الافتراضية

مالك النظام، مدير شركة، مدير فرع، مدير مبيعات، مشرف مناديب، مندوب، محصّل، سائق،
أمين مخزن، موظف مشتريات، محاسب، مدير مالي، مراجع (قراءة فقط).

أدوار إضافية تُنشأ من **الإعدادات ← الأدوار**. الأدوار النظامية لا تُعدَّل
صلاحياتها؛ يُنشأ دور جديد بدلًا منها.

**المندوب افتراضيًا لا يملك** ترحيل الفواتير، ولا رؤية التكلفة أو الربح، ولا
تعديل السعر، ولا تجاوز الحد الائتماني.

## 5. الموافقات

`approval_flows` تعرّف المستويات حسب المبلغ ونوع المستند.

- **لا يجوز اعتماد طلب تقدمت به بنفسك** — مفروض على السيرفر، لا بالتعليمات.
- طلب الموافقة يُحفظ في معاملة مستقلة **قبل** رفض العملية، حتى لا يُلغى مع
  الرفض ويترك المشرف بلا شيء يتصرف فيه.

## 6. المسؤولية لا تزول بزوال الصلاحية

إيقاف مستخدم ينهي جلساته فورًا (تُحذف رموزه)، لكن مستنداته تبقى منسوبة إليه في
`audit_logs` وفي حقول `created_by` و`posted_by` و`approved_by`. تغيير صلاحية
مستخدم لا يمحو مسؤوليته عن عمليات سابقة.

## 7. الخصوصية

تسجيل موقع المندوب:

- **أثناء وردية نشطة فقط**، وبإذن صريح مسجل في `rep_shifts.location_consent`.
- الطلب يُرفض خارج الوردية، ولا يُخزَّن بصمت.
- مدة احتفاظ قابلة للضبط (`privacy.location_retention_days`، افتراضيًا 90 يومًا).
- العرض يتطلب `field.location.view`، ويظهر **عمر كل قراءة ودقتها** مع تنبيه
  صريح بأنها آخر موقع معروف لا موقع لحظي، وأن ضعف الإشارة ليس دليل مخالفة.
