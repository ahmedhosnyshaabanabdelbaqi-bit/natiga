# حالة التنفيذ الفعلية

> **اقرأ هذه الوثيقة قبل أي قرار تشغيلي.**
> لا يذكر هذا المشروع أن ميزة «تعمل» قبل وجود اختبار يغطّيها أو تشغيل فعلي يثبتها.
> ما هو مكتوب ولم يُختبر مذكور هنا صراحةً بهذه الصفة.

آخر تحديث: بعد الجلسة الأولى من التنفيذ.

## 1. ما هو منفذ ومُختبَر

نتيجة تشغيل حزمة الاختبارات: **98 اختبارًا، 301 تحقّقًا، جميعها ناجحة**
على PostgreSQL 16.

| المجال | التغطية | الملف |
|---|---|---|
| حساب الكسور العشرية | 7 اختبارات | `tests/Unit/NumTest.php` |
| محرك المخزون | 13 اختبارًا | `tests/Feature/Domain/InventoryEngineTest.php` |
| القيد المزدوج | 12 اختبارًا | `tests/Feature/Domain/LedgerTest.php` |
| دورة المبيعات | 17 اختبارًا | `tests/Feature/Domain/SalesCycleTest.php` |
| المشتريات و GRNI | 9 اختبارات | `tests/Feature/Domain/PurchasingTest.php` |
| تحميل السيارة وإقفال اليوم | 11 اختبارًا | `tests/Feature/Domain/DayClosingTest.php` |
| المزامنة والعمل دون اتصال | 13 اختبارًا | `tests/Feature/Domain/OfflineSyncTest.php` |
| الصلاحيات على مستوى API | 16 اختبارًا | `tests/Feature/ApiAuthorizationTest.php` |

### الخصائص المُثبتة بالاختبار

- المخزون لا يُخصم مرتين: إذن التسليم يُخرج البضاعة، والفاتورة بعده لا تلمسها.
- التكلفة التاريخية مجمّدة: شراء أغلى لاحقًا لا يغير ربح فاتورة قديمة.
- المتوسط المرجح المتحرك موزون بالكمية لا وسطًا حسابيًا.
- التحويل بين المخازن لا يخلق ولا يهدم قيمة.
- الصرف بالأقرب انتهاءً، مع استبعاد المنتهي وما دون الحد الأدنى للصلاحية.
- المخزون السالب مستحيل: قيد `CHECK` في قاعدة البيانات، لا فحص في الواجهة.
- المحجوز غير متاح لمستند آخر.
- القيد غير المتوازن مرفوض في PHP وفي قاعدة البيانات.
- سطر قيد مرحّل غير قابل للتعديل؛ العكس يبقي الأصل في الدفاتر وينتج صافيًا صفرًا.
- المستند الواحد لا يُرحّل مرتين مهما أُعيد إرسال الطلب.
- التعرض الائتماني يشمل الأوامر المعتمدة غير المفوترة والحصص المحجوزة للأجهزة.
- تجاوز الحد الائتماني يُنشئ طلب موافقة يبقى بعد رفض العملية.
- استلام البضاعة يُدين المخزون ويُدائن حسابًا وسيطًا؛ الفاتورة تُقفله ولا تضيف مخزونًا.
- التكلفة المتأخرة تنقسم بين المخزون القائم والبضاعة المباعة دون إعادة كتابة التاريخ.
- تحميل السيارة تحويل لا بيع.
- معادلتا البضاعة والنقدية تتطابقان مع الأرصدة الفعلية.
- الشيكات والتحويلات البنكية لا تُضاف إلى النقدية المتوقعة.
- الإقفال النهائي ممنوع قبل اكتمال المزامنة إلا باستثناء موثق.
- فروق الجرد تُنتج مستند تسوية ينتظر اعتمادًا منفصلًا.
- إعادة إرسال عملية ميدانية لا تُنشئ مستندًا ثانيًا.
- التحصيل الميداني لا يضيع حتى لو تعذر توزيعه على الفواتير.
- الصلاحيات مفروضة على السيرفر: تغيير معرف في الرابط لا يفتح سجلًا غير مسند.
- التكلفة والربح يُحذفان من الاستجابة نفسها لمن لا يملك صلاحيتهما.

### تشغيل فعلي مُثبت

دورة كاملة عبر HTTP على الخادم الحي: استلام 1000 بتكلفة 30 ← أمر بيع 100 ←
اعتماد (حجز) ← إذن تسليم ← تأكيد ← فاتورة ← ترحيل ← تحصيل.

النتيجة: الرصيد 1000 ← 900 (خصم واحد)، تكلفة المبيعات 3000 بالتكلفة التاريخية،
**ميزان المراجعة متوازن 43,260.00 في الجانبين**.

## 2. ما هو منفذ ولم يُختبر بعد

| المكوّن | الحالة |
|---|---|
| واجهة الويب | تبني بنجاح وتعمل مقابل API حي، **بدون اختبارات واجهة آلية** |
| تطبيق المندوب (Flutter) | **الكود مكتوب ولم يُجمَّع ولم يُشغَّل** — لا يوجد Flutter SDK في بيئة الإنشاء |
| RFQ ومقارنة عروض الأسعار | جداول وواجهات API موجودة، بدون شاشات ولا اختبارات |
| مرتجع المشتريات | جداول وخدمة موجودة، بدون اختبار |
| الشيكات (دورة التحصيل والارتداد) | الجدول والحالات موجودة، الدورة غير مكتملة |
| المطابقة البنكية | الجداول فقط |
| الجرد الدوري والأعمى | الجداول والخدمات، بدون واجهة |
| العمولات والمستهدفات | الجداول وقواعد الإصدارات، الحساب غير منفذ |
| الاستيراد من Excel/CSV | جدول المهام موجود، المعالج غير منفذ |
| التصدير Excel/PDF | جدول المهام موجود، المولّد غير منفذ |
| الطوابير والمهام الخلفية | مهيأة على قاعدة البيانات، لا توجد مهام فعلية بعد |

## 3. ما هو **غير منفذ** إطلاقًا

هذه ليست نواقص مخفية — هي قرارات صريحة بعدم ادعاء ما لم يُنفذ:

- **الفاتورة الإلكترونية المصرية**: الأعمدة والحالات موجودة في `sales_invoices`
  (`e_invoice_status`, `e_invoice_uuid`)، لكن **لا يوجد أي اتصال فعلي بالمنظومة**.
  لا تُفعّل قبل: تهيئة بيانات المنشأة، واعتماد التوقيع أو الجهاز حسب المسار،
  ومطابقة الوثائق الرسمية السارية وقت التنفيذ، واختبارات قبول.
- **الطباعة الحرارية المحمولة**: تحتاج طراز طابعة محددًا وبروتوكولًا واختبارًا
  على جهاز فعلي. لا يوجد ادعاء بدعم «جميع الطابعات».
- **قوالب الطباعة A4/PDF**: غير منفذة.
- **تكاملات SMS/WhatsApp/الخرائط/بوابات الدفع**: جدول `integration_settings`
  يعرضها بحالة `not_configured` بوضوح، ولا توجد عملاء فعليون لها.
- **طريقة FIFO للتكلفة**: **غير منفذة**. الطريقة الوحيدة المنفذة والمختبرة هي
  المتوسط المرجح المتحرك. لا تُعرض FIFO كخيار في الواجهة.
- **تعدد العملات**: العمود `currency_code` موجود، لكن **لا يوجد سعر صرف تاريخي
  ولا حساب لفروق العملة**. لا يُعتمد على النظام لأكثر من عملة واحدة.
- **تعدد الشركات القانونية**: البنية تدعمه (`company_id` على كل جدول مع نطاق
  عام)، لكنه **لم يُختبر** بأكثر من شركة واحدة.
- **تتبع السيريالات**: الجدول موجود، المنطق غير منفذ.
- **Docker Compose**: غير مُنشأ بعد؛ التشغيل يدوي حسب `08-install.md`.

## 4. مخاطر معروفة

| الخطر | الأثر | التخفيف |
|---|---|---|
| مصفوفة الترحيل غير معتمدة من محاسب | قيود في حسابات خاطئة | النظام يرفض الترحيل عند وجود مفتاح غير مربوط؛ الشاشة تعرض الجاهزية |
| `bcmath` غير مثبت | أداء أبطأ في الحساب | `brick/math` يعمل بنقاء PHP والنتائج مطابقة؛ تثبيت `bcmath` أو `gmp` يسرّعه |
| لا توجد اختبارات تزامن تحت ضغط | سباق نظري على آخر كمية | الأقفال الصفّية و`CHECK` في قاعدة البيانات تمنع النتيجة الخاطئة؛ اختبار حمل موصى به قبل التشغيل |
| تطبيق المندوب لم يُجمَّع | قد لا يبني من أول مرة | منطق المزامنة على السيرفر — وهو الحرج — مُختبر بالكامل |
| لا توجد نسخ احتياطية مؤتمتة | فقد بيانات | يجب إعداد نسخ احتياطية قبل التشغيل الفعلي |

## 5. ما يجب فعله قبل التشغيل الفعلي

1. اعتماد مصفوفة الترحيل من المحاسب المسؤول.
2. مراجعة نسب الضريبة وتواريخ سريانها — الإعداد الحالي افتراضي للاختبار.
3. إعداد نسخ احتياطية مجدولة ومختبَرة الاسترجاع.
4. ضبط `ERP_OWNER_PASSWORD` وتغييرها بعد أول دخول.
5. تشغيل `php artisan migrate --force` و`db:seed` (بدون `DemoDataSeeder`).
6. تجميع تطبيق المندوب واختباره على جهاز فعلي قبل توزيعه.
7. اختبار حمل على سيناريو بيع متزامن لنفس الصنف.
