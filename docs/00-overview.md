# EG Distribution ERP — نظرة عامة على النظام

> الاسم والهوية (الشعار، الألوان، اسم الشركة، بيانات التواصل) قابلة للتغيير بالكامل من
> شاشة **الإعدادات ← بيانات الشركة**. لا يوجد أي اسم مثبّت داخل الكود.

## 1. ما هذا المشروع

نظام تشغيل متكامل لشركة توزيع: مشتريات، مخازن، مبيعات، مناديب وسيارات، تحصيل،
حسابات قيد مزدوج، وتقارير — مبني كـ **Modular Monolith** مع فصل صريح بين
منطق الأعمال (Services / Domain) وبين العرض (Controllers / UI).

النظام **ليس** نموذجًا تجريبيًا: كل رقم على الشاشة يأتي من قاعدة البيانات،
وكل حركة مخزنية أو مالية لها مستند مصدر يمكن فتحه.

| المكوّن | المسار | التقنية |

| واجهة الويب | `erp/web` | React 19 + TypeScript + Vite |

| قاعدة البيانات | — | PostgreSQL 16 |

## 3. المبادئ التي لا يُتنازل عنها

هذه القواعد مطبّقة في الكود ومغطّاة باختبارات، وليست نوايا:

1. **مصدر واحد للحقيقة في الترحيل.** السيرفر هو الجهة الوحيدة التي تُنشئ
   حركة مخزنية أو قيدًا محاسبيًا. الأجهزة الميدانية تُرسل «عمليات» لا «نتائج».
2. **الذرّية.** اعتماد أي مستند + حركاته المخزنية + قيده المحاسبي يتم داخل
   معاملة قاعدة بيانات واحدة. النجاح كامل أو التراجع كامل.
3. **عدم التكرار (Idempotency).** لكل عملية مفتاح فريد؛ إعادة الإرسال لا تُنشئ
   فاتورة أو تحصيلًا أو حركة مخزون ثانية.
4. **لا تعديل للماضي.** المستند المعتمد يحتفظ بنسخة ثابتة من سعره وخصمه وضريبته
   ومعامل تحويل وحدته. التصحيح بعكس أو إشعار، لا بحذف.
5. **الرفض الافتراضي.** كل طلب API يمر بفحص صلاحية على السيرفر. إخفاء زر في
   الواجهة ليس صلاحية.
6. **لا Float في المال.** كل المبالغ والكميات والتكاليف `NUMERIC/DECIMAL`.
7. **لا مخزون سالب.** ممنوع بقفل صفّي (`SELECT … FOR UPDATE`) + قيد `CHECK`
   في قاعدة البيانات، لا بفحص في الواجهة.
