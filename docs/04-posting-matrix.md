# مصفوفة الترحيل المحاسبي

> **هذه الوثيقة تحتاج مراجعة واعتماد المحاسب المسؤول قبل التشغيل الفعلي.**
> النظام يرفض ترحيل أي مستند يحتاج حسابًا غير مربوط، ولا يخمّن حسابًا بديلًا،
> لذلك شاشة **الإعدادات ← مصفوفة الترحيل** شرط تشغيل وليست توثيقًا.

## 1. كيف يعمل الربط

لا يوجد رقم حساب واحد مكتوب داخل الكود. محرك الترحيل يطلب «مفتاحًا» مثل
`inventory` أو `cogs`، ويحوله `AccountResolver` إلى حساب فعلي عبر جدول
`account_mappings`. تغيير دليل الحسابات أو إعادة ترقيمه لا يتطلب تعديل كود.

| المفتاح | الغرض | الافتراضي في البذرة |
|---|---|---|
| `inventory` | المخزون | 1310 |
| `inventory_in_transit` | مخزون بالطريق | 1320 |
| `accounts_receivable` | ذمم العملاء | 1200 |
| `accounts_payable` | ذمم الموردين | 2100 |
| `grni` | بضاعة مستلمة غير مفوترة | 2110 |
| `sales_revenue` | إيرادات المبيعات | 4100 |
| `sales_returns` | مرتجعات المبيعات | 4200 |
| `sales_discount` | خصم مسموح به | 4210 |
| `delivery_income` | إيرادات التوصيل | 4110 |
| `cogs` | تكلفة البضاعة المباعة | 5100 |
| `vat_output` | ضريبة مبيعات (مخرجات) | 2200 |
| `vat_input` | ضريبة مشتريات (مدخلات) | 1400 |
| `inventory_adjustment` | فروق تسويات المخزون | 5200 |
| `damage_expense` | التالف والهالك | 5210 |
| `rounding_difference` | فروق التقريب | 5900 |
| `cash_on_hand` | النقدية بالخزائن | 1110 |
| `cheques_receivable` | شيكات تحت التحصيل | 1140 |
| `customer_advances` | دفعات مقدمة من العملاء | 2300 |

حسابات الخزائن والبنوك تُربط لكل خزنة/بنك على حدة في جدوليهما، وعهدة كل محصّل
لها حساب مستقل في `custody_accounts` — حتى يكون «ما لدى المناديب الآن» رصيدًا
فعليًا في الدفاتر لا تقديرًا مستخرجًا.

## 2. المصفوفة

### 2.1 المشتريات

**استلام بضاعة** (`goods_receipt`) — *يحرك المخزون*

| | الحساب | القيمة |
|---|---|---|
| مدين | `inventory` | قيمة المستلم بالتكلفة |
| دائن | `grni` | نفس القيمة |

المورد **لا يُدان هنا**. فصل الاستلام عن الفوترة هو ما يمنع إضافة المخزون مرتين،
ويعطي رقمًا حقيقيًا لما استُلم ولم يُفوتر.

**فاتورة مورد** (`supplier_invoice`) — *لا تحرك المخزون*

| | الحساب | القيمة |
|---|---|---|
| مدين | `grni` | قيمة الاستلام كما قُيّدت |
| مدين | `vat_input` | الضريبة |
| مدين/دائن | `inventory` | فرق السعر على الكمية القائمة |
| مدين/دائن | `cogs` | فرق السعر على الكمية المباعة |
| دائن | مورد | إجمالي الفاتورة |

**تكلفة إضافية** (`landed_cost`)

| | الحساب | القيمة |
|---|---|---|
| مدين | `inventory` | الحصة المقابلة للكمية القائمة |
| مدين | `cogs` | الحصة المقابلة للكمية المباعة |
| دائن | مورد / `accounts_payable` | إجمالي التكلفة |

التوزيع بين المخزون والتكلفة يتم بنسبة الكمية المتبقية إلى الأصلية. الفواتير
القديمة **لا يُعاد حسابها**.

### 2.2 المبيعات

**فاتورة مبيعات** (`sales_invoice`)

| | الحساب | القيمة |
|---|---|---|
| مدين | عميل (آجل) أو عهدة المندوب / `cash_on_hand` (نقدي) | الإجمالي |
| دائن | `sales_revenue` | الصافي بعد الخصم وقبل الضريبة |
| دائن | `vat_output` | الضريبة |
| دائن | `delivery_income` | مصاريف التوصيل إن وُجدت |
| مدين | `cogs` | تكلفة ما خرج فعليًا |
| دائن | `inventory` | نفس القيمة |

**البيع النقدي من السيارة يُدين عهدة المندوب لا خزنة الشركة**، لأن النقدية في
جيب المندوب حتى يوردها بمحضر معتمد.

**مرتجع مبيعات** (`sales_return`)

| | الحساب | القيمة |
|---|---|---|
| مدين | `sales_returns` | الصافي |
| مدين | `vat_output` | عكس الضريبة |
| دائن | عميل أو عهدة المندوب (رد نقدي) | الإجمالي |
| مدين | `inventory` | التكلفة الأصلية للبضاعة العائدة |
| دائن | `cogs` | نفس القيمة |

المرتجع يُقيَّم **بتكلفة البيع الأصلية** المحفوظة على سطر الفاتورة، لا بمتوسط
اليوم. البيع بتكلفة 10 والاسترداد بتكلفة 12 يخلق خسارة لم تحدث.

### 2.3 الخزينة

**سند قبض** (`receipt`)

| | الحساب | القيمة |
|---|---|---|
| مدين | عهدة المحصّل / خزنة / بنك / `cheques_receivable` | المبلغ |
| دائن | عميل | المبلغ |

**لا يوجد إيراد هنا.** الإيراد اعتُرف به على الفاتورة؛ التحصيل يُسقط مديونية فقط.
الشيك يذهب إلى `cheques_receivable` ولا يُعامل نقدية حتى يُحصَّل.

**توريد نقدية** (`cash_transfer`)

| | الحساب | القيمة |
|---|---|---|
| مدين | الوجهة (خزنة/بنك) | المبلغ |
| دائن | المصدر (عهدة/خزنة) | المبلغ |

الطرفان أصول. التوريد **لا ينشئ إيرادًا**، وإلا احتُسب الإيراد مرتين.

**مصروف** (`expense`)

| | الحساب | القيمة |
|---|---|---|
| مدين | حساب المصروف | الصافي |
| مدين | `vat_input` | الضريبة |
| دائن | خزنة / بنك / عهدة | الإجمالي |

### 2.4 المخازن

**تسوية مخزون** (`stock_adjustment`)

| | الحساب | القيمة |
|---|---|---|
| مدين/دائن | `inventory` | أثر التسوية (موجب = زيادة) |
| دائن/مدين | `inventory_adjustment` أو `damage_expense` | نفس القيمة بالعكس |

**التحويل بين المخازن لا ينشئ قيدًا محاسبيًا إطلاقًا.** نقل بضاعتك من مكان إلى
آخر لا يغير ما تملكه ولا قيمته.

## 3. قواعد ملزمة في المحرك

1. **التوازن**: يُفحص في PHP قبل أي كتابة، ويُفحص مرة أخرى بـ constraint trigger
   مؤجل في PostgreSQL عند COMMIT.
2. **عدم التكرار**: فهرس فريد على
   `(company_id, source_type, source_id, purpose)` يمنع ترحيل نفس المستند مرتين
   حتى لو أُعيد إرسال الطلب.
3. **الذرّية**: المستند وحركاته المخزنية وقيده داخل معاملة واحدة.
4. **عدم تعديل المُرحّل**: trigger يمنع `UPDATE`/`DELETE` على سطور قيد مرحّل.
   التصحيح بعكس يبقي الأصل في الدفاتر ويضيف مرآته.
5. **الفترات المقفلة**: يُرفض الترحيل بتاريخ داخل فترة مقفلة.
6. **التقريب**: نصف لأعلى بعيدًا عن الصفر، عند نقطة التخزين فقط. فروق الكسور
   تذهب إلى `rounding_difference` بسطر ظاهر لا بإخفاء.
