# المعمارية

## 1. الشكل العام

**Modular Monolith**: تطبيق واحد مقسم إلى وحدات ذات حدود واضحة. اختيار متعمد
بدل الخدمات المصغرة، لأن العمليات المحاسبية والمخزنية تحتاج **معاملات ذرّية عبر
الوحدات** — والمعاملة الموزعة تعقيد بلا مقابل هنا.

```
erp/
├── api/          Laravel — منطق الأعمال وواجهة API
│   └── app/
│       ├── Domain/       ← كل منطق الأعمال
│       ├── Models/       ← Eloquent
│       ├── Http/         ← تحقق وتفويض وتفويض للخدمات
│       └── Support/      ← سياق الشركة
├── web/          React + TypeScript
└── mobile/       Flutter (تطبيق المندوب)
```

## 2. فصل المنطق عن العرض

`app/Domain` لا يعرف شيئًا عن HTTP. المتحكمات تتحقق من المدخلات، تفحص الصلاحية،
ثم تفوّض. هذا ما يجعل نفس المنطق يخدم الويب والتطبيق والمزامنة والأوامر
الطرفية بنتيجة واحدة.

| الوحدة | المسؤولية |
|---|---|
| `Domain/Inventory` | **الكاتب الوحيد** لـ stock_balances و stock_movements و item_costs |
| `Domain/Accounting` | **الكاتب الوحيد** لـ journal_entries و journal_lines |
| `Domain/Pricing` | ترتيب أولوية الأسعار والعروض وحساب السطر |
| `Domain/Credit` | التعرض الائتماني والحدود والحصص الأوفلاين |
| `Domain/Sales` | أمر البيع، التسليم، الفاتورة، المرتجع |
| `Domain/Purchasing` | الاستلام، فاتورة المورد، التكاليف الإضافية، إعادة الطلب |
| `Domain/Field` | تحميل السيارات وإقفال يوم المندوب |
| `Domain/Treasury` | التحصيل والعهد والتوريد والمصروفات |
| `Domain/Sync` | بروتوكول العمل دون اتصال |
| `Domain/Reporting` | لوحة التحكم والتقارير |

«الكاتب الوحيد» ليس عُرفًا: لا يوجد مسار آخر يكتب في هذه الجداول، ولهذا يمكن
ضمان الثوابت في مكان واحد.

## 3. دورة اعتماد مستند

```
طلب HTTP
  ├─ تحقق من المدخلات
  ├─ فحص الصلاحية (رفض افتراضي)
  └─ خدمة المجال
       └─ DB::transaction
            ├─ قفل صفّي على الأرصدة
            ├─ حركات مخزنية (InventoryService)
            ├─ بناء القيد وفحص توازنه
            └─ ترحيل القيد (LedgerService)
       ↓ نجاح المعاملة
  └─ طابور: التكاملات الخارجية (قابلة لإعادة المحاولة)
```

التكاملات الخارجية **بعد** نجاح المعاملة، لا داخلها. خدمة بطيئة أو معطلة يجب
ألا تُفشل عملية بيع، وعملية ملغاة يجب ألا تُرسل إشعارًا.

## 4. الثوابت ومكان فرضها

| الثابت | المكان |
|---|---|
| لا مخزون سالب | قيد `CHECK` في PostgreSQL |
| المحجوز ≤ الفعلي | قيد `CHECK` |
| القيد متوازن | فحص في PHP + constraint trigger مؤجل |
| سطر مُرحّل غير قابل للتعديل | trigger في PostgreSQL |
| مستند واحد = قيد واحد | فهرس فريد جزئي |
| عملية ميدانية واحدة = مستند واحد | فهرس فريد على مفتاح عدم التكرار |
| عزل الشركات | نطاق عام على كل نموذج |

الفرض في قاعدة البيانات مقصود: القيد الذي يعيش في الكود فقط يسقط عند أول مسار
جديد ينسى استدعاءه.

## 5. الأرقام

لا شيء مالي هو `float`. الأعمدة `NUMERIC`، والحساب في PHP عبر `Domain\Support\Num`
المبني على `brick/math`، وفي Flutter عبر `Dec` المبني على `BigInt`.

الدقة: 8 خانات للحساب الوسيط، 4 للكميات، 2 للمال المُرحّل. التقريب نصف لأعلى
عند نقطة التخزين فقط، لا في كل خطوة.

## 6. الوقت

يُخزَّن بتوقيت UTC ويُعرض بتوقيت `Africa/Cairo`. النظام يميز:

- **وقت الحدث** (`moved_at`, `delivered_at`) — متى حدث فعلًا
- **تاريخ المستند** (`invoice_date`) — التاريخ التجاري
- **تاريخ الترحيل** (`entry_date`) — الذي يحدد الفترة المالية

## 7. تعدد الشركات

كل جدول تشغيلي يحمل `company_id`، ونطاق عام يقيّد كل استعلام تلقائيًا. تجاوزه
يحتاج `withoutCompanyScope()` صراحةً، فنسيان شرط `where` لا يسرّب بيانات شركة
أخرى.

> البنية تدعم عدة شركات لكنها **لم تُختبر** بأكثر من واحدة. راجع `09-status.md`.
