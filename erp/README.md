# محمد فياض — نظام إدارة شركة التوزيع

نظام متكامل لإدارة شركة توزيع: المشتريات والموردين، الأصناف والمخازن، المبيعات والعملاء،
المناديب والتحصيلات، السيارات والتوزيع، الحسابات والتقارير، ولوحات تحكم حسب الدور.

> اسم النظام واسم الشركة والهوية **قابلة للتغيير من الإعدادات** بعد التثبيت.

---

## البنية

```
erp/
  backend/     Laravel 13 + PHP 8.4 + PostgreSQL 16  — المنطق والـAPI
  frontend/    React 19 + TypeScript + Vite          — واجهة عربية RTL
  mobile/      Flutter                               — تطبيق المندوب (مصدر غير مبني)
  docs/        الوثائق الكاملة
  docker-compose.yml
```

---

## التشغيل السريع

```bash
cd erp
cp .env.example .env        # عرّف DB_PASSWORD و ERP_BACKUP_KEY
docker compose run --rm api php artisan key:generate --show   # ضع الناتج في APP_KEY
docker compose up -d --build
docker compose exec api php artisan erp:install
```

الواجهة: http://localhost:8080 · API: http://localhost:8000/api/v1

تفاصيل التشغيل بلا Docker وعلى شبكة داخلية: `docs/06-OPERATIONS.md`.

**لرفع النظام على خادمك خطوة بخطوة (Docker أو تثبيت مباشر على Ubuntu): [`DEPLOY.md`](DEPLOY.md).**

## ما يميز هذا التنفيذ

| الضمان | كيف تحقق |
|---|---|
| **لا Float في أي نتيجة مالية** | كل الأعمدة `NUMERIC`، والحساب عبر `brick/math` بدقة داخلية 10 خانات |
| **القيد لا يختل** | `CHECK` على التوازن + قيد فريد يمنع الترحيل المزدوج + رفض الترحيل خارج معاملة |
| **المخزون لا يسلب** | قفل صفوف الأرصدة + `CHECK (qty_base >= 0)` — مُختبَر باتصالين متزامنين |
| **التكلفة التاريخية لا تتغيّر** | تكلفة البيع تُحفظ في سطر الفاتورة؛ شراء لاحق بسعر أعلى لا يمس الفواتير القديمة |
| **لا خصم مخزون مزدوج** | مالك واحد لحركة البضاعة (`is_stock_owner`) بين الفاتورة وإذن التسليم |
| **لا عدّ مزدوج للائتمان** | التعرض = المستحقات + غير المفوتر من الطلبات + الحصص الأوفلاين المتبقية |
| **العهدة ليست خزنة** | التحصيل يدخل عهدة المندوب، والإيداع ينقلها للخزنة **بلا إيراد جديد** |
| **لا تكرار عند إعادة الإرسال** | مفتاح عدم تكرار لكل عملية؛ الإرسال الثاني يُرجع الإيصال المحفوظ |
| **التكلفة لا تُسرَّب** | لا تُرسل في الاستجابة أصلًا لغير المخوّل — لا إخفاء في الواجهة |
| **الرفض الافتراضي** | ما لا يُمنح صراحةً يُرفض، والتحقق في السيرفر على كل طلب |
| **اتجاه صحيح لكل لغة** | العربية RTL بقائمة يمين، والإنجليزية LTR بقائمة شمال — مقيس بالبكسل لا مفترضًا |

## الاختبارات

```bash
cd backend
php artisan test                                  # 56 اختبارًا · 296 تحققًا
php artisan test --filter=ReferenceScenarioTest   # السيناريو المرجعي الإلزامي
```

الواجهة تُفحص بالمتصفح آليًا: 25 شاشة بالعربية و22 فحصًا للغة والاتجاه
(موضع القائمة الجانبية مقيس بالبكسل في اللغتين على الحاسوب والموبايل).

تعمل على PostgreSQL نفسه لأن قيود القاعدة والأقفال جزء من الضمانات المختبَرة.
النتائج الكاملة والأرقام المقيسة: `docs/07-TEST-REPORT.md`.

## تنبيهان قبل التشغيل الفعلي

1. **مصفوفة الترحيل غير مُراجَعة.** أُنشئت بقواعد افتراضية للتجهيز فقط، ويجب أن يراجعها
   المحاسب المسؤول ويعتمدها قبل الترحيل على دفاتر حقيقية.

2. **الفاتورة الإلكترونية المصرية وتعدد العملات غير مُنفَّذين.** الحقول موجودة بلا منطق.
   لا تَعِد العميل بهما. التفاصيل في `docs/08-KNOWN-ISSUES.md`.
