# المشكلات المعروفة وما لم يُنفَّذ

هذا الملف يذكر بصراحة ما **لم** يُنفَّذ أو نُفِّذ جزئيًا، حتى لا يُبنى قرار تشغيلي على وعد غير قائم.

---

## ١. لم يُنفَّذ إطلاقًا

| البند | الوضع الفعلي | الأثر التشغيلي |
|---|---|---|
| **تعدد العملات** | الحقول (`currency_code`, `exchange_rate`) موجودة في الجداول لكن **لا يوجد منطق** لأسعار الصرف التاريخية أو فروق الصرف | لا تستخدم النظام لعمليات بعملة غير الجنيه. لا تَعِد العميل بدعم عملات |
| **الفاتورة والإيصال الإلكتروني المصريان** | الحقول (`etax_status`, `etax_uuid`, `etax_response`) موجودة فقط. لا يوجد تكامل ولا توقيع ولا تقديم | كل الفواتير حالتها `not_submitted`. **الربط الضريبي لا يعمل** ويحتاج تنفيذًا كاملًا وفق الوثائق السارية وقت التنفيذ |
| **المصادقة متعددة العوامل** | `mfa_secret` و`mfa_enabled` حقلان بلا منطق | الحسابات الحساسة محمية بكلمة مرور وحدود محاولات فقط |
| **المطابقة البنكية** | غير موجودة | تتم يدويًا خارج النظام |
| **قائمة المركز المالي والتدفقات النقدية** | غير موجودتين | ميزان المراجعة وقائمة الدخل متاحان |
| **بوابة B2B** | غير موجودة | — |
| **التحضير والالتقاط والتعبئة** (Picking/Packing) | غير موجودة | التجهيز يتم بإذن تسليم مباشر |
| **اقتراح إعادة الطلب الآلي** | غير موجود؛ يوجد فلتر النواقص فقط | التخطيط يدوي |
| **توصيات نقل المخزون وتقدير الاحتياج** | غير موجودة | — |
| **مولّد PDF خادمي** | غير موجود؛ الطباعة عبر المتصفح | التصدير لـPDF يتم من نافذة الطباعة |
| **مساعد الاستعلام بالذكاء الاصطناعي** | غير موجود | الوظائف الأساسية مستقلة عنه كما هو مطلوب |

## ٢. الخلفية جاهزة والواجهة ناقصة

الجداول والنماذج والقيود موجودة ومُرحَّلة، لكن لا توجد خدمة ترحيل أو شاشة:

| البند | الجداول الجاهزة | الناقص |
|---|---|---|
| طلب الشراء وعروض الموردين ومقارنتها | `purchase_requests`, `supplier_quotes`, `purchase_orders` | الخدمات والشاشات |
| مدفوعات الموردين ومرتجع المشتريات | `supplier_payments`, `purchase_returns` + التخصيصات | خدمات الترحيل |
| التكاليف الإضافية (نقل/تخليص) | `landed_costs`, `landed_cost_allocations` | خدمة التوزيع والترحيل (دالة `Dec::allocate` جاهزة ومُختبَرة) |
| عرض السعر وأمر البيع وإذن التسليم | `quotations`, `sales_orders`, `delivery_notes` بكل الحقول | خدمات الترحيل والشاشات |
| الجرد الفعلي (أعمى/دوري) | `inventory_counts` + `movement_during_count` | خدمة التجميد والعد والاعتماد |
| محضر تسليم العهدة | `custody_handovers` | الخدمة والشاشة |
| المستهدفات | `targets` | محرك الاحتساب والشاشة |
| الموافقات متعددة المستويات | `approval_rules/steps/requests` | محرك التنفيذ والشاشة |
| استيراد Excel/CSV | `import_batches` بقيد `file_hash` فريد يمنع التكرار | خدمة القراءة والمعاينة والتطبيق |
| مركز الاستثناءات | `exception_signals` | مولّد الإشارات والشاشة |
| الشكاوى والوعود بالسداد | `customer_complaints`, `payment_promises` | الشاشات |
| تصدير التقارير الكبيرة عبر طابور | `report_jobs` | العامل ورابط التحميل المحمي |

## ٣. مُنفَّذ بقيود

| البند | القيد |
|---|---|
| **تطبيق المندوب (Flutter)** | المصدر مكتوب في `erp/mobile` لكن **لم يُبنَ ولم يُشغَّل ولم يُختبَر** — لا يوجد Flutter SDK في بيئة التطوير. لا توجد حزمة APK. ما يعمل ومُختبَر هو **API المزامنة** من جهة الخادم |
| **الطباعة** | أنماط `@media print` للفاتورة والتقارير على A4 عبر المتصفح. لا قوالب حرارية ولا طباعة محمولة — دعم الطابعات يحتاج إعداد طراز وبروتوكول واختبارًا فعليًا على جهاز |
| **التكاملات (SMS/WhatsApp/خرائط/دفع)** | البنية جاهزة (`integration_settings` + `notifications_outbox`) وتُظهر الخدمة غير المهيأة بوضوح بحالة `skipped_not_configured`. **لا يوجد اتصال فعلي بأي مزود** |
| **الطوابير** | مهيأة على قاعدة البيانات. `deploy/install.sh` يثبّت وحدتي systemd (`erp-worker` و`erp-scheduler`) ويشغّلهما، لكن **لم يُتحقق من تشغيلهما فعليًا** — بيئة الاختبار بلا systemd كـ PID 1 |
| **النسخ الاحتياطية** | أمرا `erp:backup` و`erp:restore-test` يعملان ومُختبَران محليًا. الجدولة والنسخة خارج جهاز التشغيل **إعداد تشغيلي** يجب ضبطه عند النشر |
| **الضرائب** | `tax_codes` مؤرخة وبلا نسبة افتراضية — عمدًا. يجب أن يضبطها المحاسب قبل أي بيع خاضع للضريبة |

## ٤. ملاحظات تشغيلية مهمة

1. **مصفوفة الترحيل غير مُراجَعة.** كل قواعد `posting_rules` حالتها `is_reviewed = false`. لا تُشغّل النظام فعليًا قبل مراجعة المحاسب المسؤول واعتمادها.

2. **الأداء لم يُقَس على بيانات واقعية الحجم.** الأرقام المسجلة في `07-TEST-REPORT.md` من بيئة تطوير ببيانات صغيرة، ولا تصلح كوعد أداء إنتاجي.

3. **لم يُجرَ اختبار اختراق.** الضمانات المُختبَرة هي: الرفض الافتراضي، نطاق السجل، حجب التكلفة، حدود محاولات الدخول، وقيود قاعدة البيانات.

4. **استعادة النسخة الاحتياطية اختُبرت محليًا فقط** بأمر `erp:restore-test` الذي يستعيد إلى قاعدة مؤقتة ويقارن عدد الصفوف. اختبار استعادة كامل على بيئة منفصلة ما زال مطلوبًا قبل الاعتماد.

5. **حزمة Android غير موجودة.** لا تُسلَّم أي APK.

6. **ما لم يُتحقق منه في حزمة النشر.** التثبيت بـ `deploy/install.sh` جُرِّب فعليًا من الصفر
   حتى الدخول من المتصفح (انظر `07-TEST-REPORT.md` قسم ١٣)، لكن ثلاثة أشياء لم تُشغَّل:
   - **`php-fpm`** غير مثبت في بيئة الاختبار، فسطر `fastcgi_pass` في إعداد Nginx
     صحيح نحويًا لكن لم يمرّ طلب حقيقي عبره؛ مسار الطلبات اختُبر بـ`proxy_pass` بدلًا منه.
   - **وحدتا systemd** لم تُشغَّلا (لا systemd في البيئة).
   - **حزمة Docker Compose** لم تُبنَ (تعذّر سحب الصور).

   أول ما تفعله بعد التثبيت على خادمك: `curl http://localhost/api/v1/health`
   و`systemctl status erp-worker erp-scheduler`.
